# 标签库业务联动推进记录

## 目标

PRD 一期基础数据联动补齐：完成标签库与业务流程的统一 ID 接入。

## 本轮完成

- 后端新增业务标签快照字段：
  - `jobs.tag_refs`
  - `seeker_profiles.tag_refs`
  - `resume_structured_profiles.tag_refs`
- 新增 Alembic 迁移：
  - `y4h6i8j0k124_add_business_tag_refs.py`
  - `z5i7k9m1n235_add_resume_structured_profile_tag_refs.py`
- 新增公开只读标签接口：
  - `GET /api/v1/base-data/tags/public`
- 岗位发布支持 `tag_ids`：
  - 校验标签必须存在且 active。
  - 保存 `tag_refs` 快照：`id/name/category/color`。
  - 响应返回 `tag_refs`。
  - 传入 `tag_ids` 时，展示 `tags` 使用标签库名称，减少 mock 字符串来源。
- 求职意向支持 `tag_ids`：
  - 校验标签必须存在且 active。
  - 保存并返回 `tag_refs`。
- 结构化简历画像支持 `tag_ids`：
  - 创建结构化画像时支持提交 `tag_ids`。
  - 确认解析结果时支持提交 `tag_ids`。
  - 保存并返回 `tag_refs`，候选人搜索优先使用结构化画像标签，兼容回退到求职意向标签。
- 搜索支持按统一标签 ID 过滤：
  - `GET /api/v1/search/jobs?tag_id=...`
  - `GET /api/v1/search/resumes?tag_id=...`
- 前端接入：
  - 招聘端发布岗位页从公开标签库加载标签，多选后提交 `tag_ids`。
  - 求职者完善信息页从公开标签库加载能力标签，多选后提交 `tag_ids`。
  - 求职者解析结果确认页从公开标签库加载画像标签，多选后确认保存到结构化简历画像。
  - 求职者画像页展示结构化画像 `tag_refs`。
  - 求职端首页岗位搜索增加标签筛选，调用搜索 API 时传 `tag_id`。
  - 招聘端人才池与人才入口从公开标签库加载候选人标签，按 `tag_id` 调用候选人搜索 API 并展示 `tag_refs`。
