# P3 人岗匹配与规则配置协作计划

## 阶段目标

P3 的目标是把“真实简历画像 + 真实岗位 + 可解释匹配 + 后台可管理规则”这条链路做稳。

P3 解决三个问题：

1. 求职者看到的匹配分来自真实简历画像和真实岗位。
2. 匹配结果可解释，能说明分数、权重和主要命中/缺口。
3. 匹配规则从代码固化逐步演进为后台可管理、可版本化、可实验、可审计的能力。

截至 R-P3-07，P3 规则版主线已经完成到“规则实验真实生效与匹配审计”。向量匹配、LLM 实时评分、自动调权等能力仍放在后续阶段。

## 已具备能力

### 求职者侧

- 可以基于真实简历解析/确认结果计算岗位匹配分。
- 匹配结果包含总分、等级、推荐结论、摘要、亮点和缺口。
- 每个维度都有分数、权重、贡献分、说明和规则逻辑。

### 管理端

- 可以查看规则配置列表和详情。
- 可以编辑规则维度并保存为新版本。
- 可以查看版本历史、版本对比。
- 可以通过回滚操作基于历史版本生成新版本。
- 可以创建规则实验入口。
- 可以查看实验效果和最近匹配审计记录。

### 后端规则能力

- 规则配置已落库。
- 支持 `scope`、`template_key`、`version`、`status`。
- 支持默认规则 fallback，数据库规则异常时不阻断匹配。
- 支持运行时按 `job_id:{job_id}` 优先、再 `global` 的顺序选择规则。
- 支持 running 实验的 control/treatment 分流。
- 支持稳定 AB bucket：同一实验、求职者和岗位组合会稳定落到同一 bucket。
- 支持匹配结果审计和实验效果聚合。

## 关键接口

匹配接口：

```text
GET /api/v1/matches/jobs/{job_id}/me
```

规则配置：

```text
GET  /api/v1/matches/rule-configs
GET  /api/v1/matches/rule-configs/default
GET  /api/v1/matches/rule-configs/{config_id}
POST /api/v1/matches/rule-configs/{config_id}/versions
GET  /api/v1/matches/rule-configs/{config_id}/history
GET  /api/v1/matches/rule-configs/{config_id}/compare/{target_config_id}
POST /api/v1/matches/rule-configs/{config_id}/rollback
POST /api/v1/matches/rule-configs/templates
```

实验与审计：

```text
GET  /api/v1/matches/rule-experiments
POST /api/v1/matches/rule-experiments
GET  /api/v1/matches/rule-experiments/{experiment_id}/effects
GET  /api/v1/matches/audits
```

## 当前不做

P3 当前规则版主线暂不做：

- 向量库和 embedding 匹配。
- LLM 实时评分。
- LLM 动态生成规则。
- 根据投递转化率自动调权。
- 长周期匹配缓存和离线重算。
- 复杂权限体系和审批流。
- 实验统计显著性分析。

这些能力需要等规则底座、审计数据量和管理端闭环稳定后再推进。
