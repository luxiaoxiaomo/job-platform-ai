# 简历画像能力梳理

这份文档用于拆清楚“当前画像页该降级还是实现”。结论是：当前先降级，完整画像等 P2 结构化解析结果出来后再实现。

## 当前问题

上传简历后，页面会让用户进入“我的简历画像”。但当前画像页只有一部分数据来自真实接口：

- 姓名、职业方向、经验、学历来自 `seeker_profiles`。
- 当前简历文件名和解析状态来自 `seeker_resumes` / `latest_parse_run`。
- 技能标签有一部分是从 `profile + parsed_snapshot` 关键词推断。

但以下内容仍然是 mock：

- 画像标签云。
- 雷达图能力维度。
- 能力分数。
- AI 总结。
- 薪酬建议。
- 风险点和提升建议。

这会造成误导：用户以为上传后的画像是 AI 基于简历解析生成的，但实际上 P1 只完成了原文抽取和 chunk。

## 决策

短期先降级，长期再实现。

```text
P0/P1: 画像页降级为“简历状态与基础信息”
P2: 基于 structured_json 和核心明细表生成基础画像
P3/P4: 接标签、关键词、RAG、匹配解释后再做完整 AI 画像
```

不要在 P1 阶段展示雷达图、AI 分数、薪酬建议这些看起来像真实智能结论的内容。

## P0/P1：必须降级的内容

目标：页面不再误导用户。

前端需要处理：

1. 移除或隐藏 mock 雷达图。
2. 移除或隐藏 mock 能力分数。
3. 移除或隐藏 mock AI 总结。
4. 移除或隐藏 mock 薪酬建议。
5. 页面标题或文案改为“简历基础信息”或“简历解析状态”。
6. 明确展示当前解析能力：
   - 已上传。
   - 已抽取原文。
   - 暂未完成结构化 AI 解析。
   - 等待用户确认。

可以保留：

- 当前简历文件名。
- 解析状态。
- 基础信息。
- 原文预览入口。
- 上传历史入口。

## P2：基础画像实现

P2 在结构化 JSON 和核心明细表完成后，可以实现“基础画像”。

数据来源：

- `resume_structured_profiles.structured_json`
- `resume_basic_infos`
- `resume_educations`
- `resume_work_experiences`
- `resume_projects`
- `resume_skills`
- `resume_certificates`

可展示能力：

- 基础信息完整度。
- 教育背景。
- 工作年限。
- 核心技能。
- 项目经验摘要。
- 证书摘要。
- 字段置信度。
- 待确认字段数量。

这时仍然不建议展示复杂雷达图，除非每个维度都有清晰计算规则。

## P3/P4：完整 AI 画像

完整画像要等标签、关键词和 RAG 起来后再做。

数据来源：

- `resume_tags`
- `resume_keywords`
- `resume_chunks` + embedding
- `resume_structured_profiles`
- 岗位 JD 结构化结果

可展示能力：

- 能力标签云。
- 项目亮点。
- 风险点。
- 岗位匹配解释。
- 能力维度评分。
- 薪酬建议。
- 提升建议。

注意：薪酬建议必须单独设计规则和数据来源，不能只靠简历字段随便生成。

## 画像能力分层

| 能力 | 当前是否可做 | 阶段 | 数据来源 |
| --- | --- | --- | --- |
| 简历文件状态 | 可以 | P1 | `seeker_resumes`, `resume_uploads`, `resume_parse_runs` |
| 原文预览 | 可以 | P1 | `resume_extracted_texts` |
| 基础信息展示 | 可以 | P1 | `seeker_profiles` |
| 基础信息完整度 | 可以 | P2 | `resume_structured_profiles`, 明细表 |
| 技能摘要 | 可以 | P2 | `resume_skills` |
| 项目摘要 | 可以 | P2 | `resume_projects` |
| 标签云 | 后置 | P3 | `resume_tags` |
| 风险点 | 后置 | P3 | structured JSON / LLM |
| 能力雷达图 | 后置 | P4 | 标签、关键词、规则评分 |
| 薪酬建议 | 后置 | P4 | 岗位市场数据、城市、年限、技能、历史薪酬规则 |
| 人岗匹配解释 | 后置 | P4 | JD 结构化结果 + 简历结构化结果 + RAG |
