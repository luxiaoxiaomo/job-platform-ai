# R-P3-06 Rule Version Management Contract

## Scope

R-P3-06 extends match rule administration after R-P3-05. It adds:

- Multiple rule templates through `template_key` and `template_name`.
- Version comparison between any two configs in the same history family.
- Rollback by creating a new version from a historical config.
- Gray / AB test entry management.

Runtime job matching still defaults to the active `global/default` rule. Traffic routing and experiment result analysis are deferred to R-P3-07.

## Rule Config Additions

`MatchRuleConfigResponse` adds these backwards-compatible fields:

```json
{
  "template_key": "default",
  "template_name": "Default template"
}
```

Version numbering is scoped by:

```text
scope + strategy + template_key
```

Activating a new version archives only active versions in the same scope, strategy, and template.

## Endpoints

### List Rule Configs

```text
GET /api/v1/matches/rule-configs?scope=global&template_key=default
```

Filters are optional. Response remains `MatchRuleConfigListResponse`.

### Create Template

```text
POST /api/v1/matches/rule-configs/templates
```

Request:

```json
{
  "name": "Tech job rule template V1",
  "description": "Template for tech jobs",
  "template_key": "tech_jobs",
  "template_name": "Tech jobs",
  "status": "active",
  "scope": "job_category:tech",
  "dimensions": []
}
```

Response:

```json
{
  "message": "rule_config_template_created",
  "config": {}
}
```

### Compare Versions

```text
GET /api/v1/matches/rule-configs/{base_id}/compare/{target_id}
```

Response includes base config, target config, dimension-level diffs, and a summary:

```json
{
  "summary": {
    "added": 0,
    "removed": 0,
    "changed": 2,
    "unchanged": 4
  },
  "dimensions": [
    {
      "key": "skill",
      "change_type": "changed",
      "base_weight": 35,
      "target_weight": 40,
      "weight_delta": 5,
      "enabled_changed": false,
      "logic_changed": false
    }
  ]
}
```

### Rollback

```text
POST /api/v1/matches/rule-configs/{current_id}/rollback
```

Request:

```json
{
  "target_config_id": 1,
  "status": "active",
  "name": "Rollback to V1"
}
```

Rollback never mutates the historical version. It creates a new version copied from `target_config_id`; if active, it archives the previous active version in the same template.

### Gray / AB Test Entries

```text
GET /api/v1/matches/rule-experiments
POST /api/v1/matches/rule-experiments
```

Create request:

```json
{
  "name": "Rule AB test",
  "description": "Gray entry for rule experiment",
  "scope": "global",
  "template_key": "default",
  "status": "draft",
  "traffic_percent": 25,
  "control_config_id": 1,
  "treatment_config_id": 2,
  "audience": {}
}
```

`control_config_id` and `treatment_config_id` must belong to the same scope and template as the experiment.
