## 主要重复与冲突

### 1. 计划与执行

现有能力：

- Agents: `writing-plans-0.1.0`
- Agents: `executing-plans-0.1.0`
- Claude superpowers: `writing-plans`
- Claude superpowers: `executing-plans`
- Agents: `code-1.0.4`

判断：

功能高度重叠，但分属不同工具生态。不要删除。Codex 当前默认仍优先使用 Agents 侧已有 `writing-plans` / `executing-plans`；需要中文增强工作流时，可以显式调用 `superpowers-zh` 内的对应 skill。Claude Code 使用 plugin 内置版本。

### 2. 调试

现有能力：

- Agents: `debug-pro-1.0.0`
- Claude superpowers: `systematic-debugging`
- Agents: `code-1.0.4`

判断：

`debug-pro` 更偏命令和语言级调试手册；`systematic-debugging` 更偏方法论。Codex 当前保留 `debug-pro` 作为主用调试 skill；复杂根因追踪时可以显式调用 `superpowers-zh/systematic-debugging`。

### 3. 验证与测试

现有能力：

- Agents: `test-runner-1.0.0`
- Agents: `code-1.0.4`
- Claude superpowers: `verification-before-completion`
- Claude superpowers: `test-driven-development`

判断：

Codex 有测试执行能力，当前系统/开发者规则也已经要求验证。`superpowers-zh` 安装后提供了 `verification-before-completion`，适合在大任务交付前显式调用；小任务不强制走完整流程。

### 4. 代码审查

Codex 对“review”已经有明确行为规则：优先列 bug、风险、回归和测试缺口。Claude 的 code-review skills 不必复制。安全审查继续使用 `security-auditor` 或 Codex 原生安全 skills。

### 5. 联网与网页访问

现有能力：

- Agents: `agent-reach`
- Agents: `web-access`
- Codex: `playwright`
- 系统内置 web 工具

判断：

这是当前最容易重复触发的区域。

建议主次：

- `agent-reach`：作为互联网调研和平台路由入口。
- `web-access`：只在需要真实浏览器、登录态、CDP、动态页面交互时使用。

- 系统 `web`：用于快速搜索、读取公开网页、GitHub 页面核实。

后续如果要真正去重，优先调整 `agent-reach` 与 `web-access` 的触发描述，避免“所有 URL 同时触发两个 skill”。

## superpowers-zh 使用策略

当前状态：已安装，但不建议作为所有任务的无条件强制流程。

原因：

- Claude Code 已经有原版 `superpowers`。
- Codex/Agents 已有大量等价能力。
- `superpowers-zh` 与现有 planning/debugging/testing/review skills 有明显重复。
- 全局安装会影响所有项目，应通过调用规则控制使用范围。

建议使用方式：

- 大任务、PRD 对齐、复杂调试、交付前验证：可以显式调用 `superpowers-zh` 相关 skill。
- 小任务、单点修复、简单查询：继续使用当前 Codex/Agents 默认能力。
- 中文团队规范类任务：优先使用 `chinese-code-review`、`chinese-documentation`、`chinese-git-workflow`、`chinese-commit-conventions`。
- 不建议把 `using-superpowers` 的“任何响应前必须调用 skill”规则作为当前 Codex 会话的强制规则；这会显著增加流程成本。
