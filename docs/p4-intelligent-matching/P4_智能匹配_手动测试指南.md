# P4 智能匹配手动测试指南

本文用于验收 P4 当前已完成的策略管理、离线评估、管理端页面和运行时智能评分边界。基础登录、岗位、投递和消息流程不在本文重复说明。

## 1. 测试范围

本轮覆盖：

1. 管理员创建、查看、更新和克隆智能匹配策略。
2. 管理员运行离线评估并查看评估报告。
3. 离线评估区分真实/人工样本与 demo/mock 样本。
4. 普通求职者、招聘者不能访问智能匹配管理接口。
5. react-admin 管理端可以完成策略列表、创建、详情、编辑、克隆和评估报告查看。
6. 当数据库存在 `active` 智能策略时，求职者岗位匹配和招聘者投递匹配进入 `intelligent_hybrid_v1` 运行时评分。
7. 本地 `local_profile_text` provider 可返回混合评分；provider 不可用或未配置时，系统降级到 `rule_baseline` 并记录审计信息。

本轮不覆盖：

1. 生产级外部向量数据库或向量服务。当前只有本地确定性 provider。
2. 智能策略正式激活/发布治理。当前管理 API 创建草稿，不能完成生产发布闭环。
3. 规则实验 treatment 与智能策略的绑定。
4. 生产环境灰度、监控、回滚和上线决策。

## 2. 前置条件

后端服务启动后，打开 Swagger：

```text
http://localhost:8003/docs
```

前端服务启动后，管理员可打开：

```text
http://localhost:5174/#/admin-ra/intelligent-matching/strategies
```

当前管理页面支持草稿管理和离线评估，不提供正式激活/发布操作。运行时边界测试需要数据库中已经存在 `active` 智能策略；如果没有，匹配接口继续使用规则基线。

需要准备：

1. 一个管理员账号 token。
2. 一个求职者账号 token。
3. 一个招聘者账号 token。
4. 至少一个已有的规则配置 ID，也就是 `match_rule_configs.id`。如果不确定，可以先在 Swagger 调用：

```text
GET /api/v1/matches/rule-configs
```

从返回列表里取一个 `id` 作为 `base_rule_config_id`。

## 3. 建议测试顺序

按下面顺序测，最省时间：

1. 在管理端查看智能策略列表。
2. 管理员创建智能策略草稿。
3. 管理员查看策略详情并更新草稿。
4. 管理员克隆策略。
5. 管理员运行真实/人工样本离线评估。
6. 管理员查看评估报告。
7. 管理员运行 demo/mock 样本离线评估。
8. 用求职者/招聘者 token 访问管理接口，确认被拒绝。
9. 如果环境中已有 `active` 智能策略，调用求职者岗位匹配或招聘者投递匹配，检查 `source.strategy`、`match_source` 和审计快照。
10. 检查 provider 不可用时是否返回 `rule_baseline`，并记录 `vector_store_unavailable`。

## 4. 用例 1：创建智能策略

接口：

```text
POST /api/v1/matches/intelligent/strategies
```

权限：

```text
admin
```

请求示例：

```json
{
  "name": "manual-hybrid-strategy-v1",
  "description": "Manual smoke test strategy",
  "base_rule_config_id": 1,
  "vector_recall": {
    "enabled": true,
    "top_n": 100,
    "min_similarity": 0.62,
    "candidate_source": "job_resume_profile"
  },
  "hybrid_weights": {
    "rule_score": 0.7,
    "vector_score": 0.2,
    "profile_coverage_score": 0.1,
    "behavior_quality_score": 0
  },
  "fallback_policy": "rule_baseline"
}
```

注意：把 `base_rule_config_id` 替换成你本地真实存在的规则配置 ID。

预期结果：

```text
HTTP 200
status = draft
fallback_policy = rule_baseline
base_rule_config_id = 请求中的规则配置 ID
```

记录返回的 `id`，后续用作 `strategy_id`。

## 13. 通过标准

本次手动测试通过，需要满足：

1. 管理员可以完成创建、列表、详情、更新和克隆策略。
2. 管理员可以运行离线评估并查看报告。
3. 真实/人工样本评估可以返回 `eligible_for_gray`。
4. demo/mock 样本评估必须返回 `demo_only`，并带风险说明。
5. 求职者和招聘者访问智能策略/离线评估接口返回 `403`。
6. 管理端可以完成策略与评估报告的本地操作流程。
7. 没有 `active` 智能策略时，匹配保持规则基线；存在 `active` 策略时，运行时返回可审计的智能评分或明确的降级结果。

1. 离线评估指标是 MVP 阶段的确定性摘要，不代表生产向量召回效果。
2. 管理端已经接入，但现有证据仅覆盖本地开发和 demo 浏览器验收。

5. provider 未配置或不可用时，系统记录 `vector_store_unavailable` 并降级到 `rule_baseline`。
6. 规则实验 treatment 尚未绑定智能策略。
7. 生产环境 E2E、监控、上线决策和回滚证据尚未完成。
