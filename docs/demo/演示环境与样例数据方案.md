# 演示环境与样例数据方案

## 目标

本方案用于准备空岗发布平台的本地/演示环境，使演示能同时覆盖两类能力：

1. 核心业务闭环：企业认证、岗位发布与审核、求职者浏览/搜索、简历与结构化档案、投递、聊天、联系方式交换、状态流转。
2. Match Quality：规则配置、匹配审计、分层质量、异常识别、调优建议、实验置信度和运营看板输出。

演示数据只允许进入本地或专用 demo 数据库，不允许连接生产库或复用生产凭据。

   期望输出包含 `ok: true`，并生成：

## 回滚与清理规则

### 运行前规则

1. 任何 seed 或 cleanup 之前，先确认数据库不是生产库。
2. 写入数据必须带有可识别前缀或来源字段，例如 `RP401`、`DEMO`、`source=rp401_demo`。
3. 运行 manifest 必须记录所有账号、岗位、投递、会话、联系方式交换、规则实验和截图。
4. 删除类操作必须先 dry-run 列出待删除对象，不允许直接清理未知范围数据。

### RP401 seed 清理边界

`seed_rp401_demo.py` 自带 `cleanup_previous_demo()`，每次重跑会清理：

- `source=rp401_demo` 的 match audits。
- 上述 audit 关联岗位的 applications、favorites、visits、jobs。
- 上述 audit 关联的 demo seeker users。
- 名称为 `RP401 Demo Experiment` 的实验。

它会复用或更新 admin、recruiter 和标准职位，不会把这些基础账号/标准职位作为清理对象。若需要删除这些保留对象，必须单独写明 dry-run、备份和审批。

### 完整业务闭环数据清理边界

完整业务闭环数据可能由页面、API 或脚本混合生成。清理时只能使用 manifest 中记录的对象 ID：

1. 先导出或截图当前 manifest。
2. dry-run 查询 job、application、conversation、contact exchange、resume/profile、company certification 的当前状态。
3. 确认对象标题、公司名、展示名或来源前缀为本次 demo。
4. 按业务依赖从子对象到主对象清理：messages/contact exchanges -> applications -> visits/favorites -> jobs -> certifications -> demo users。
5. 清理后再次读取 summary：公开岗位列表、投递列表、消息列表、Match Quality summary 不应残留本次 demo 对象。

若任何对象缺少 manifest 记录或前缀不明确，停止自动清理，改为人工核验。

## 验收门槛

演示环境可交付前必须满足：

1. 公司、岗位、求职者、简历/档案、匹配规则、投递、聊天、联系方式交换和 Match Quality 输出都有真实或明确标注的 demo 证据。
2. 每项数据来源标注为 `seeded`、`generated` 或 `manual`。
3. 回滚/清理规则已写入本方案，并在脚本运行前完成确认。
4. Match Quality 页面能展示 segment、anomaly、tuning suggestion 和 experiment confidence。
5. 联系方式交换必须通过 contact exchange API 完成，不把聊天中的明文手机号当作有效对接证据。
