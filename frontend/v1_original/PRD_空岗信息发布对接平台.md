## 1. 背景与目标

### 1.1 产品背景

当前招聘市场存在以下核心痛点：

| 痛点维度 | 具体问题描述 | 影响群体 |
|----------|-------------|---------|
| 信息不对称 | 中小企业空岗信息缺乏高效发布渠道，岗位信息散落于各社交群、朋友圈，触达范围有限 | 招聘者（中小企业为主） |
| 信息失真 | 虚假招聘、过期岗位、薪资不透明等现象导致应聘者信任成本高 | 应聘者 |
| 匹配效率低 | 招聘者与应聘者之间缺乏结构化的信息对接机制，大量无效沟通消耗双方精力 | 双方 |
| 隐私暴露风险 | 招聘者不希望公开企业真名或个人真实联系方式时缺乏保护手段 | 招聘者 |
| 缺乏数据支撑 | 招聘效果无法量化评估，岗位曝光量、应聘者质量等数据缺失 | 招聘者 |

本平台旨在构建一个以"空岗信息发布-精准推送-双向对接"为核心链路的招聘服务平台，通过结构化岗位信息、智能关键词订阅推送、隐私保护等能力，为中小企业招聘者与求职者搭建高效、可信、便捷的对接桥梁。

### 1.2 目标用户

| 角色 | 用户画像 | 核心诉求 | 使用频次（预估） |
|------|---------|---------|-----------------|
| 招聘者-HR | 中小企业人力资源专员/经理，25-45岁，负责日常招聘执行，熟悉微信生态，对招聘效率有明确诉求 | 快速发布空岗、收到匹配简历、降低招聘成本 | 每周3-5次 |
| 招聘者-企业主 | 小微企业创始人/合伙人，30-55岁，亲自参与招聘，关注用人成本，对平台操作简便性要求高 | 低成本招人、了解企业实力背书效果 | 每周1-2次 |
| 招聘者-猎头/代理 | 人力资源服务从业者，为多家企业代招，需要批量管理和转发能力 | 批量发布、高效转发推荐、数据统计 | 每日1-3次 |
| 应聘者-在职求职 | 22-40岁在职人员，利用碎片时间浏览机会，对隐私保护敏感，不希望被现单位发现 | 浏览匹配岗位、隐私安全、便捷投递 | 每周3-7次 |
| 应聘者-待业求职 | 20-45岁待业/应届人群，求职意愿强烈，对岗位信息完整度和反馈速度要求高 | 快速获取岗位详情、在线投递、收到反馈 | 每日1-3次 |
| 平台管理员 | 平台运营人员，负责内容审核、会员管理、基础数据维护 | 高效审核、数据可控、运营灵活 | 每日持续 |

### 1.3 业务目标与成功指标

| 目标维度 | 具体目标 | 成功指标（一期上线后6个月内） | 度量方式 |
|----------|---------|-------------------------------|---------|
| 用户规模 | 建立初始双边用户池 | 注册招聘者 >= 2,000家；注册应聘者 >= 20,000人 | 平台注册数据 |
| 供给活跃 | 保证岗位信息持续供给 | 月活跃发布岗位 >= 5,000条；月新增岗位 >= 1,500条 | 岗位发布数据 |
| 对接效率 | 促成有效双向对接 | 月均留言互动 >= 10,000次；岗位平均收到简历 >= 3份/条 | 互动与投递数据 |
| 用户留存 | 验证产品核心价值 | 招聘者次月留存率 >= 35%；应聘者次月留存率 >= 25% | 留存分析 |
| 信息质量 | 建立可信平台形象 | 企业认证通过率 >= 80%；投诉率 <= 2% | 审核与投诉数据 |
| 营收验证 | 验证商业模式可行性 | 付费企业转化率 >= 5%（一期不强制，二期重点） | 付费数据 |

## 2. 需求概述

### 2.1 产品定位

面向中小企业招聘者与求职者的空岗信息发布与对接平台，以微信服务号/小程序为主要载体，提供岗位发布、关键词订阅推送、双向留言互动等核心功能，支持隐私保护（虚拟名/虚拟联系方式），通过结构化信息提升招聘对接效率。

### 2.2 核心业务流程

```
[招聘者注册认证] --> [填写空岗信息] --> [企业认证 + 平台审核] --> [岗位发布上线]
                                                                    |
                                                                    v
[应聘者注册] --> [设置关键词订阅] --> [收到推送] --> [查看职位概要] --> [补充个人信息] --> [查看完整信息] --> [留言互动/投递]
                                                        |
                                                        v
                                          [招聘者收到通知] --> [查看应聘者信息] --> [留言回复/转发推荐]
```

### 2.3 一期 MVP 功能范围

一期聚焦核心对接链路的打通，功能范围如下：

| 模块 | 功能点 | 优先级 |
|------|--------|--------|
| 招聘者-注册认证 | 微信认证、单位信息填写、联系信息填写 | P0 |
| 招聘者-空岗发布 | 岗位名称/城市/薪资/职责/要求填写、模板调用 | P0 |
| 招聘者-发布审核 | 企业资质上传、公开信息选择、平台审核 | P0 |
| 招聘者-信息管理 | 修改已发布信息 | P0 |
| 招聘者-消息互动 | 接收应聘者留言、关键词推送 | P0 |
| 招聘者-简历查看 | 查看应聘者补充的个人信息 | P1 |
| 招聘者-转发推荐 | 生成转发链接推荐应聘者给其他招聘者 | P1 |
| 招聘者-数据统计 | 浏览量（人数、人次） | P1 |
| 招聘者-个人主页 | 招聘者个人中心 | P1 |
| 应聘者-注册 | 微信认证、实名/虚拟名选择 | P0 |
| 应聘者-关键词订阅 | 设置关注关键词 | P0 |
| 应聘者-接收推送 | 平台推送职位概要 | P0 |
| 应聘者-补充信息 | 填写基本信息/联系方式/能力/期望后查看完整职位 | P0 |
| 应聘者-留言对话 | 与用人单位留言互动 | P0 |
| 应聘者-转发推荐 | 生成转发链接推荐职位给其他应聘者 | P1 |
| 应聘者-职位收藏 | 收藏职位 | P1 |
| 应聘者-个人主页 | 应聘者个人中心 | P1 |
| 平台管理-审核 | 企业资质审核、岗位信息审核 | P0 |
| 平台管理-基础管理 | 标签库、职位库、JD模板库管理 | P1 |
| 平台管理-会员管理 | 会员分级管理 | P2 |

### 2.4 二期/三期功能概览（不在一期范围内，仅在排期中体现）

**二期**：智能化升级（天眼查对接、AI JD代写、画像匹配推送、简历解析、AI面试等）

**三期**：生态化扩展（大数据报告、增值服务、社区互动、投诉举报体系等）

## 3. 功能详细设计

### 3.1 招聘者端功能模块

#### 3.1.1 注册认证

**功能描述：** 招聘者通过微信授权登录完成基础注册，并完善单位信息、联系信息等必要资料，获得发布岗位的资格。平台支持企业真名与虚拟名并行机制，保护招聘者隐私的同时确保平台可追溯。

**用户故事：**

| 编号 | 用户故事 | 验收条件 |
|------|---------|---------|
| US-R-001 | 作为一名企业HR，我希望通过微信快速注册平台，以便尽快发布空岗信息 | 微信授权后3步内完成基础注册 |
| US-R-002 | 作为一名企业主，我希望使用虚拟名发布岗位，以免暴露企业真实身份 | 虚拟名模式下岗位展示不含企业真名，但平台后台保留真名信息 |
| US-R-003 | 作为一名猎头，我希望注册时关联已有企业信息，避免重复填写 | 输入企业名后系统尝试匹配已有企业并自动填充信息 |

**优先级：** P0

**业务规则：**

| 编号 | 规则描述 |
|------|---------|
| BR-R-001 | 注册必须通过微信授权，获取微信OpenID作为唯一标识 |
| BR-R-002 | 注册时必须阅读并勾选同意《平台使用规则》《隐私保护协议》《免责条款》 |
| BR-R-003 | 单位真名为必填字段，仅平台后台可见；虚拟名为选填字段，用于前台展示 |
| BR-R-004 | 若招聘者填写的企业名称与平台已有企业重复且信息冲突，系统标记异常并提醒人工核查 |
| BR-R-005 | 联系信息中至少需填写一种有效联系方式（手机号/微信号/企业邮箱三选一必填） |
| BR-R-006 | 个人名片图片为选填，若上传则需人工审核后方可展示 |
| BR-R-007 | 企业真名、统一社会信用代码、联系真姓名属于敏感信息，加密存储，仅平台管理员和认证审核流程可访问 |
| BR-R-008 | 同一微信号仅可注册一个招聘者账号 |
| BR-R-009 | 注册完成后默认获得"普通招聘者"身份，需完成企业认证后方可发布岗位 |

**交互流程：**

```
Step 1: 用户进入平台（微信服务号/小程序）
  --> Step 2: 点击"注册/登录"，触发微信授权弹窗
  --> Step 3: 用户确认授权，获取微信头像/昵称/OpenID
  --> Step 4: 展示《平台规则》等协议，用户阅读并勾选同意
  --> Step 5: 进入"单位信息填写"页面
    - 输入单位真名（必填，系统尝试匹配已有企业）
    - 若匹配成功，展示已有信息供确认/微调
    - 若匹配失败或信息冲突，提示用户核实
    - 填写虚拟名（选填）
  --> Step 6: 进入"联系信息填写"页面
    - 填写联系人真姓名/虚拟名
    - 填写联系方式（手机号/微信号/企业邮箱至少一项）
    - 上传个人名片（选填）
  --> Step 7: 进入"基本信息填写"页面
    - 选择区域、城市、行业、人员规模、经营规模
    - 填写地址（选填）
  --> Step 8: 提交注册，进入"待完善"状态
  --> Step 9: 引导用户进行企业认证以解锁发布权限
```

**异常处理表：**

| 异常场景 | 处理策略 | 用户提示 |
|----------|---------|---------|
| 微信授权失败 | 提示重试，记录失败日志 | "微信授权失败，请检查网络后重试" |
| 用户拒绝授权 | 允许浏览公开内容，限制发布/互动功能 | "授权后可使用完整功能，是否前往授权？" |
| 企业名称与已有记录重复且信息冲突 | 标记为"信息待核实"，允许提交但限制发布直至审核通过 | "检测到该企业已有注册信息且存在差异，请核实后提交，平台将在1个工作日内完成核查" |
| 疑似假冒企业注册（关键词/模型初筛） | 进入人工审核队列，冻结发布权限 | "您的注册信息正在审核中，预计1-2个工作日完成" |
| 手机号格式错误 | 前端实时校验，阻断提交 | "请输入有效的手机号码" |
| 必填字段未填写 | 前端校验阻断提交，高亮未填字段 | "请完善必填信息后提交" |
| 同一微信号重复注册 | 直接登录已有账号 | "该微信已注册账号，正在为您登录" |

#### 3.1.2 填写空岗信息

**功能描述：** 招聘者在完成注册认证后，可创建空岗信息。系统提供结构化表单引导填写，岗位名称支持标准职位库下拉+自定义输入，工作职责与任职要求支持调用系统模板后微调编辑。

**用户故事：**

| 编号 | 用户故事 | 验收条件 |
|------|---------|---------|
| US-R-010 | 作为一名HR，我希望通过标准职位库快速选择岗位名称，减少手动输入 | 输入关键词后200ms内展示匹配候选项 |
| US-R-011 | 作为一名HR，我希望调用系统提供的职责/要求模板，然后在此基础上修改 | 选择模板后内容自动填入编辑框，可自由编辑 |
| US-R-012 | 作为一名企业主，我希望一条岗位可以覆盖多个工作城市 | 工作城市支持多选，最多选择10个城市 |

**优先级：** P0

**业务规则：**

| 编号 | 规则描述 |
|------|---------|
| BR-R-010 | 岗位名称为必填项，优先从平台标准职位库中选取；若无匹配项，可手动输入自定义名称，自定义名称需经平台审核 |
| BR-R-011 | 工作城市支持多选，至少选择1个，最多10个；城市列表基于平台维护的标准城市库 |
| BR-R-012 | 薪资待遇范围为必填项，采用"最低-最高"格式，单位为"元/月"或"元/年"（可切换）；最低值不得高于最高值；系统提供常见薪资区间供快速选择 |
| BR-R-013 | 工作职责为必填项，字数限制50-2000字；可从JD模板库选取模板后编辑修改 |
| BR-R-014 | 任职要求为必填项，字数限制50-2000字；可从JD模板库选取模板后编辑修改 |
| BR-R-015 | 岗位信息填写完成后可保存为草稿，草稿无数量上限 |
| BR-R-016 | 未通过企业认证的招聘者可以填写岗位信息但不可提交发布 |
| BR-R-017 | 同一招聘者最多可同时发布50条在线岗位（含已发布+审核中状态） |

**交互流程：**

```
Step 1: 招聘者进入"发布岗位"入口
  --> Step 2: 系统检查企业认证状态
    - 未认证：提示"请先完成企业认证"，引导跳转认证页
    - 已认证：进入岗位填写页
  --> Step 3: 填写岗位名称
    - 输入关键词，系统从职位库模糊匹配并下拉展示
    - 选择标准职位名称 或 点击"自定义输入"手动填写
  --> Step 4: 选择工作城市（多选下拉框，支持搜索）
  --> Step 5: 填写薪资待遇范围
    - 选择计薪方式（月薪/年薪/日薪/面议）
    - 输入最低值和最高值（或勾选"面议"）
  --> Step 6: 填写工作职责
    - 点击"使用模板"按钮，弹出模板选择面板
    - 选择模板后内容自动填入富文本编辑区
    - 用户可自由编辑修改内容
  --> Step 7: 填写任职要求（同Step 6流程）
  --> Step 8: 预览填写内容
  --> Step 9: 选择"保存草稿"或"提交发布"
    - 保存草稿：存入草稿箱，可随时编辑
    - 提交发布：进入发布审核流程（见3.1.3）
```

**异常处理表：**

| 异常场景 | 处理策略 | 用户提示 |
|----------|---------|---------|
| 自定义岗位名称包含敏感词 | 阻断提交，高亮敏感内容 | "岗位名称包含不当用语，请修改后重新提交" |
| 薪资范围最低值高于最高值 | 前端校验阻断提交 | "薪资范围最低值不可高于最高值" |
| 工作职责/要求字数不足50字 | 阻断提交 | "内容过短，请补充至50字以上" |
| 模板库无匹配模板 | 展示空白编辑区，引导用户自行编写 | "暂无匹配模板，请手动填写" |
| 同时发布数量达上限（50条） | 阻断新建 | "当前在线岗位已达上限（50条），请关闭部分岗位后再发布" |
| 网络中断导致保存失败 | 本地缓存未提交内容，恢复后提示继续编辑 | "网络异常，内容已本地保存，网络恢复后可继续编辑" |

#### 3.1.3 发布审核

**功能描述：** 招聘者提交岗位发布申请后，需完成企业资质认证（营业执照上传等）和平台内容审核。审核通过后岗位正式上线展示。招聘者可自主选择对外公开的信息维度。

**用户故事：**

| 编号 | 用户故事 | 验收条件 |
|------|---------|---------|

### 3.4 供需匹配与排序策略

作为双边平台，供需匹配与内容排序是核心产品策略。一期采用基础匹配机制，为二期智能匹配预留数据基础。

#### 3.4.1 岗位-应聘者匹配规则（一期）

| 匹配维度 | 匹配逻辑 | 应用场景 |
|----------|---------|---------|
| 关键词匹配 | 应聘者设定的订阅关键词与岗位名称/职责/要求进行文本匹配 | 岗位推送给应聘者 |
| 城市匹配 | 应聘者订阅的城市筛选条件与岗位工作城市交叉匹配 | 岗位推送给应聘者 |
| 薪资匹配 | 应聘者订阅的薪资范围与岗位薪资区间重叠匹配 | 岗位推送给应聘者 |

#### 3.4.2 排序策略（一期）

| 场景 | 排序规则 | 权重说明 |
|------|---------|---------|
| 应聘者搜索结果 | 发布时间（新优先）> 薪资匹配度 > 关键词命中数 | 一期以时间为主排序因子 |
| 推送优先级 | 关键词精确匹配 > 模糊匹配；高完整度岗位信息 > 低完整度 | 精确命中的岗位优先推送 |
| 招聘者收到的应聘者推送 | 信息完整度 > 注册时间（新优先）> 关键词命中数 | 信息完整的应聘者优先展示 |
| 首页推荐 | 最新发布岗位 + 运营手动置顶岗位 | 运营可干预推荐位 |

#### 3.4.3 二期匹配策略预告

二期将引入画像匹配模型，基于标签体系进行多维度加权匹配：

- **岗位画像**：基于岗位标签（行业、职能、技能要求、薪资级别）构建多维向量
- **应聘者画像**：基于简历标签（学历、经验、技能、期望）构建多维向量
- **匹配算法**：余弦相似度 + 业务规则约束（城市、薪资硬性条件过滤）
- **排序因子**：匹配度得分 > 活跃度 > 信息完整度 > 响应率

### 3.5 平台佣金/抽成/结算规则

#### 3.5.1 一期收费模型

一期为冷启动阶段，核心目标是积累双边用户和验证产品价值，**不收取佣金或服务费**。

| 收费项 | 一期策略 | 说明 |
|--------|---------|------|
| 岗位发布 | 免费 | 吸引招聘者入驻 |
| 简历查看 | 免费 | 降低招聘者使用门槛 |
| 应聘者优先展示 | 免费 | 吸引应聘者注册 |

## 8. 风险与依赖

### 8.1 风险评估

| 风险编号 | 风险描述 | 影响程度 | 发生概率 | 应对措施 |
|----------|---------|---------|---------|---------|
| RISK-001 | 冷启动双边用户不足：招聘者发布岗位无应聘者查看，应聘者注册无岗位可看 | 高 | 高 | 1. 运营提前储备种子岗位（>=200条）再开放应聘者注册；2. 与HR社群合作定向招募首批招聘者 |
| RISK-002 | 虚假企业信息：假冒企业注册发布虚假招聘 | 高 | 中 | 1. 营业执照OCR+人工双重审核；2. 高风险企业交叉审核；3. 建立举报机制 |
| RISK-003 | 信息泄露风险：敏感信息（企业真名、个人手机号）泄露 | 高 | 低 | 1. 敏感数据加密存储；2. 严格权限控制；3. 定期安全审计 |
| RISK-004 | 微信生态依赖风险：微信接口政策变更、模板消息限制 | 中 | 中 | 1. 关注微信开放平台政策变化；2. 建设站内消息体系作为备用通道；3. 考虑小程序+服务号双端部署 |
| RISK-005 | 内容合规风险：岗位信息含歧视性内容、虚假薪资等 | 中 | 中 | 1. 建立内容审核标准和敏感词库；2. 人工+自动双重过滤；3. 定期更新合规标准 |
| RISK-006 | 竞品分流：Boss直聘、猎聘等成熟平台虹吸用户 | 中 | 高 | 1. 差异化定位（中小企业+隐私保护+虚拟名机制）；2. 聚焦区域/行业垂直场景；3. 免费策略吸引价格敏感用户 |
| RISK-007 | 推送效果不达预期：微信模板消息触达率低 | 中 | 中 | 1. 优化推送时段策略；2. 引导用户开启通知权限；3. 丰富推送内容形式提升点击率 |
| RISK-008 | 一期功能范围蔓延：需求追加导致工期延长 | 中 | 高 | 1. 严格执行MVP范围，新需求进入二期Backlog；2. 变更需经产品评审委员会审批 |
