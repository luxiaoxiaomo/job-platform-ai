# 简历解析底座协作看板

本看板用于 Codex 与 Claude Code 在同一个工作目录下协作。任何任务开工前，先确认 Owner 和文件边界，避免两边同时改同一批文件。

## 状态约定

| 状态 | 含义 |
| --- | --- |
| `Todo` | 未开始 |
| `In Progress` | 正在做，只允许 Owner 修改对应文件 |
| `Blocked` | 被依赖、环境或接口阻塞 |
| `Review` | 已完成，等待另一个 AI 或用户检查 |
| `Done` | 已验证完成 |

## Owner 约定

| Owner | 默认职责 |
| --- | --- |
| Codex | 后端、数据库迁移、API contract、后端测试 |
| Claude | 前端页面、交互、浏览器验证、字段映射评审 |
| Both | 需要先对齐 contract，再分别改后端/前端 |

## 文件锁规则

- 任务进入 `In Progress` 后，Owner 锁定对应文件边界。
- 非 Owner 不修改锁定文件；必须修改时，先在对话中说明原因。
- Alembic migration 永远由 Codex 创建。
- 前端 seeker 页面默认由 Claude 修改。
- `docs/简历解析底座技术设计.md` 由 Codex 维护；Claude 提建议，不直接改最终方案文档。

## 每日同步格式

每次同步只写三件事：

```text
Owner:
Doing:
Changed files:
Blocked by:
Next:
```

示例：

```text
Owner: Codex
Doing: R-P1-01 创建四张底座表迁移
Changed files: backend/job-platform/app/modules/resume/models.py, alembic/versions/xxxx_add_resume_parse_foundation.py
Blocked by: 无
Next: 跑 alembic upgrade head 和后端测试
```

## 完成定义

单个任务 Done 需要满足：

- 代码或文档已经落地。
- Owner 已自测。
- 如果涉及 API，contract 已更新。
- 如果涉及 UI，前端 build 或浏览器验证已通过。
- 没有越界修改对方负责文件。
