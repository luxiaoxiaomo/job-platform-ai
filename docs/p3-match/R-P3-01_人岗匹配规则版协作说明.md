# R-P3-01 人岗匹配规则版协作说明

## 背景

P2 已经把“简历上传 -> 结构化解析 -> 用户确认 -> 画像聚合”这条链路打通。现在求职者画像页已经能基于真实数据展示基础信息、教育经历、工作经历、项目经历、技能、证书和完整度。

但前端的“AI 人岗匹配分析”页面仍然使用 mock 数据。用户看到的匹配分、雷达图、命中点和建议文案并没有基于真实简历画像和真实岗位数据计算。这是 P3 最应该先补的缺口。

P3 的第一步不直接做 LLM、向量库或复杂推荐引擎。先做一个规则版 V1，把真实数据链路跑通，让页面从 mock 变成真实可解释结果。后续再升级标签体系、向量语义匹配、LLM 解释文案和后台规则配置。

## 当前可用基础

### 人才侧

后端已有画像聚合接口：

```http
GET /api/v1/resumes/me/profile-summary
```

可用字段包括：

- 基础信息：姓名、性别、年龄、手机号、邮箱、最高学历、工作年限、当前城市、目标岗位、期望薪资
- 摘要列表：教育经历、工作经历、项目经历、技能、证书
- 完整度和待确认状态

### 岗位侧

当前岗位表已有可计算字段：

- `title`
- `city`
- `salary_min`
- `salary_max`
- `experience`
- `education`
- `description`
- `requirement`
- `tags`

这足够支撑第一版规则匹配。

## 本轮目标

让 `/seeker/match/:id` 这个“AI 人岗匹配分析”页面改为真实数据驱动。

后端提供规则版匹配 API。前端调用该 API 展示：

- 总匹配分
- 匹配等级
- 是否建议投递
- 分项得分
- 命中点
- 缺口点
- 评分权重
- 数据来源说明

## 后端接口草案

```http
GET /api/v1/matches/jobs/{job_id}/me
Authorization: Bearer <seeker token>
```

权限：

- 仅 `seeker` 可调用。
- 岗位必须存在且可被求职者查看。
- 求职者没有简历画像时，返回 422 或明确的 `profile_required` 错误。

## 默认评分权重

第一版先硬编码默认权重，并在接口返回 `weights`，方便前端解释“分数怎么算出来的”。

| 维度 | key | 权重 |
| --- | --- | --- |
| 技能匹配 | `skill` | 35 |
| 经验年限 | `experience` | 20 |
| 学历匹配 | `education` | 15 |
| 城市匹配 | `city` | 10 |
| 薪资匹配 | `salary` | 10 |
| 岗位意向 | `intention` | 10 |

后续 P3-03 再抽成配置表，不在 R-P3-01 一次性做复杂后台配置。

## 规则版 V1 计算建议

### 技能匹配

来源：

- 岗位 `tags`
- 岗位 `requirement` 中识别出的技能词
- 简历 `summaries.skills`

规则：

- 命中核心技能越多，分数越高。
- 岗位没有技能标签时，根据标题、描述和要求做简单关键词识别。
- 返回 matched/missing。

### 经验年限

来源：

- 岗位 `experience`
- 简历 `basic_info.work_years`

规则：

- 简历年限满足要求：100
- 略低于要求：60 到 80
- 明显不足：30 到 50
- 岗位不限经验：80

### 学历匹配

来源：

- 岗位 `education`
- 简历 `basic_info.highest_education`

规则：

- 满足或高于要求：100
- 低一级：60 到 80
- 缺失学历：50
- 岗位不限学历：80

### 城市匹配

来源：

- 岗位 `city`
- 简历 `basic_info.current_city`

规则：

- 完全一致：100
- 简历城市缺失：50
- 不一致：40

### 薪资匹配

来源：

- 岗位 `salary_min/max`
- 简历 `basic_info.expected_salary`

规则：

- 期望薪资与岗位区间有重叠：100
- 可解析但不重叠：50
- 简历未填写期望薪资：60

### 岗位意向

来源：

- 岗位 `title`
- 简历 `basic_info.target_position`

规则：

- 标题/意向关键词高度重合：100
- 有部分词重合：70
- 缺失目标岗位：50
- 完全不相关：30

## 前端展示建议

前端不要再展示 mock 的固定 92%。建议按后端返回：

- 顶部显示 `overall_score` 和 `recommendation`
- 雷达图或进度条使用 `dimensions`
- “优势”使用 `highlights`
- “待补充”使用 `gaps`
- 小字展示 `source.strategy` 和权重信息

失败态：

- `profile_required`：提示“请先上传并确认简历解析结果”
- `job_not_found`：提示“岗位不存在或已下线”
- 其它错误：提示“暂时无法生成匹配分析”

## 暂不做的事

本轮不要做：

- LLM 调用
- 向量库
- embedding
- 招聘者自定义权重后台
- 行业/岗位族差异化规则
- 双向候选人排序
- 商业化计费

这些可以放到后续 P3-03 之后。
