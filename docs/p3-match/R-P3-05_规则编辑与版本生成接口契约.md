# R-P3-05 规则编辑与版本生成接口契约

## 目标

R-P3-05 将人岗匹配规则从只读配置推进到可编辑配置。编辑不覆盖原记录，而是基于当前规则生成一个新版本，用于后续版本链、回滚、对比和灰度能力。

## 接口

### 获取规则列表

`GET /api/v1/matches/rule-configs`

权限：`admin`

查询参数：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `scope` | string | 可选，默认不过滤 |
| `job_id` | number | 可选，当前阶段传入时仍回落到 `global` |
| `skip` | number | 默认 `0` |
| `limit` | number | 默认 `20`，最大 `100` |

响应：`MatchRuleConfigListResponse`

### 获取规则详情

`GET /api/v1/matches/rule-configs/{config_id}`

权限：`admin`

响应：`MatchRuleConfigResponse`

### 获取历史版本

`GET /api/v1/matches/rule-configs/{config_id}/history`

权限：`admin`

响应：`MatchRuleConfigListResponse`

排序：按 `version` 倒序。

第一版历史页只要求展示版本链，不要求版本对比和回滚。

### 保存为新版本

`POST /api/v1/matches/rule-configs/{config_id}/versions`

权限：`admin`

语义：

- 基于 `{config_id}` 读取源规则。
- 校验维度 `key` 不重复。
- 校验启用维度的有效权重大于 `0`。
- 按同一 `scope + strategy` 计算 `next_version = max(version) + 1`。
- 新记录的 `parent_version_id` 指向源规则 ID。
- 如果新版本状态为 `active`，同一 `scope + strategy` 下旧 `active` 版本归档为 `archived`，并写入 `effective_to`。
- 返回新版本规则，前端保存成功后跳转到新版本详情页。

请求体：

```json
{
  "name": "默认人岗匹配规则 V2",
  "description": "调整技能权重并停用城市维度",
  "status": "active",
  "scope": "global",
  "effective_from": null,
  "effective_to": null,
  "dimensions": [
    {
      "key": "skill",
      "label": "技能匹配",
      "weight": 40,
      "enabled": true,
      "description": "岗位技能与简历技能匹配",
      "scoring_method": "命中岗位技能越多，分数越高",
      "logic": {
        "type": "keyword_match"
      },
      "sort_order": 1
    }
  ]
}
```

响应：

```json
{
  "message": "rule_config_version_created",
  "config": {
    "id": 2,
    "name": "默认人岗匹配规则 V2",
    "strategy": "rule_v1",
    "scope": "global",
    "status": "active",
    "version": 2,
    "parent_version_id": 1,
    "configured_total_weight": 100,
    "effective_total_weight": 100,
    "dimensions": []
  }
}
```

## 前端约定

- `react-admin` 资源名：`match-rules`。
- `dataProvider.update('match-rules', params)` 不调用 `PUT/PATCH`，而是调用 `POST /versions`。
- 保存成功后使用返回的 `config.id` 跳转到 `/admin-ra/match-rules/{new_id}/show`。
- 历史页路由为 `/admin-ra/match-rules/{id}/history`。
- 历史页中的“查看”跳转到对应版本详情 `/admin-ra/match-rules/{version_id}/show`。

## 验收

1. 管理员能打开规则列表和详情。
2. 管理员能进入编辑页修改权重、启停维度、说明和逻辑 JSON。
3. 保存时调用 `POST /api/v1/matches/rule-configs/{id}/versions`。
4. 保存成功后产生新版本，不覆盖源版本。
5. 新版本为 `active` 时，旧 active 版本变为 `archived`。
6. 历史版本页能看到新旧版本，并能跳回任意版本详情。
7. 非管理员不能访问规则管理写接口。
