# 实施规划：真实业务闭环打通

本文档用于交给另一个 Codex 继续实现。目标不是重做产品，而是基于当前代码，把主业务链路从 mock 原型推进到可测试的真实闭环。

## 当前目标

打通这条最小业务闭环：

```text
招聘者发布岗位
-> 管理员审核岗位
-> 求职者前台看到岗位
-> 求职者留言咨询或投递
-> 招聘者看到留言或投递
-> 招聘者处理线索
-> 形成一次有效对接
```

一期不要追求所有页面都真实化。优先处理会影响这条链路的关键页面和接口。

## 当前已完成的关键能力

### 真实留言和聊天

已实现真实对话链路：

- 求职者点击留言咨询后，进入真实聊天，不再自动发送默认消息。
- 求职者和招聘者都能发送消息。
- 招聘者可以收到求职者消息。
- 消息内容里手打手机号、邮箱、微信号时，后端会做脱敏。

### 联系方式交换

已实现并修过以下问题：

- 可以请求交换联系方式。
- 对方可以同意或拒绝。
- 同意后，招聘者端只显示应聘者联系方式。
- 同意后，应聘者端只显示招聘者联系方式。
- 刷新后仍然能看到已交换联系方式。
- 招聘者端能看到应聘者手机号，不再被求职者资料里的 `phone_public` 挡住。
- 应聘者端在等待对方同意时，会轻量轮询刷新状态。

### P1：统一岗位发布、审核、前台展示的数据源

这是最重要的真实闭环。

需要确认并补齐：

- 招聘者发布岗位后，岗位进入待审核或可审核状态。
- 管理后台岗位审核列表来自真实后端。
- 管理员审核通过后，岗位状态变为前台可见。
- 求职者首页/岗位列表只展示审核通过或招聘中的真实岗位。
- 求职者岗位详情来自真实岗位接口。

### P2：梳理投递制和留言制的关系

产品要求两个都要保留。

建议定义为：

```text
留言咨询：创建或进入 conversation。
立即投递：创建 application。
交换联系方式：conversation 里的后续对接动作。
```

不要把投递和留言混成一个动作。

岗位详情页建议保留两个主按钮：

```text
立即投递
留言咨询
```

联系方式交换只应该出现在聊天页里，不应该一开始就在岗位详情里直接交换。

需要确认：

- 求职者是否可以对同一岗位重复投递。
- 投递后是否还能留言。
- 留言后是否还能投递。
- 招聘者端如何同时看到“已投递”和“已沟通”。

后端重点看：

```text
backend/job-platform/app/api/v1/applications.py
backend/job-platform/app/modules/application/
backend/job-platform/tests/test_api/test_applications.py
```

前端重点看：

```text

frontend/wechat-prototype/src/recruiter/RecruiterTalentPool.jsx
frontend/wechat-prototype/src/recruiter/RecruiterPages.jsx
```

验收标准：

```text

2. 求职者能看到自己的真实投递记录。
3. 招聘者能看到该岗位收到的真实投递。
4. 招聘者能打开投递详情。
5. 留言咨询和投递互不阻塞。
```

### P3：招聘者线索处理入口统一

招聘者端至少要有两个入口可用：

```text
消息列表：处理留言会话。
投递/候选人列表：处理求职者投递。
```

当前真实消息列表已经接入过一部分，需要继续检查投递/候选人相关页面是否仍然是 mock。

优先让招聘者能完成：

```text
看到谁投递了哪个岗位
看到谁留言了哪个岗位
进入详情
回复消息
查看投递信息
```

暂时可以不做复杂的招聘流程状态，比如面试、录用、淘汰。先支持最小处理。

### P4：补对接成功记录和统计

PRD 里“联系方式交换成功”是一期对接成功的核心定义。

当前交换功能可用，但还缺统计闭环。

建议后续补：

- 联系方式交换成功时记录一次 `contact_exchange` 或 equivalent event。
- 招聘者后台能看到对接成功数。
- 管理后台或统计接口能看到平台层面的成功对接数。

这个不是当前第一优先级。真实岗位和投递链路先通。

## 最小最终验收

另一个 Codex 完成后，应该能手工跑通：

```text
1. 招聘者登录或注册。
2. 招聘者创建一个新岗位。
3. 管理员在审核后台看到该岗位。
4. 管理员审核通过。
5. 求职者前台看到该岗位。
6. 求职者进入岗位详情。
7. 求职者点击留言咨询，进入真实聊天。
8. 招聘者消息列表看到该对话并回复。
9. 求职者点击立即投递。
10. 招聘者投递/候选人入口看到该投递。
11. 双方在聊天中交换联系方式。
12. 招聘者端看到应聘者联系方式；应聘者端看到招聘者联系方式。
```

只要这 12 步能稳定完成，主业务闭环就算打通。
