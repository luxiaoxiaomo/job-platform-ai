## 1. 角色定义

| 角色 | 描述 | 核心目标 |
|------|------|----------|
| **招聘者** | 企业HR或招聘负责人，通过平台发布空岗信息并管理招聘流程 | 高效发布岗位、筛选候选人、完成招聘 |
| **应聘者** | 求职者，通过平台浏览岗位信息并与招聘方互动 | 发现合适岗位、展示自身能力、获得工作机会 |
| **平台管理员**（隐式） | 负责审核、风控和平台运营 | 确保信息真实合规、维护平台秩序 |

#### US-1.1 通过微信完成招聘者身份认证登录

| 属性 | 值 |
|------|-----|
| **角色** | 招聘者 |
| **需求** | 我希望通过微信扫码或授权快速完成平台登录认证 |
| **价值** | 以便无需繁琐注册流程即可进入平台开始使用 |
| **优先级** | P0 |
| **Story Points** | 3 |
| **前置依赖** | 无 |

**验收标准（AC）：**

```gherkin
AC-1.1.1 正常流程：微信扫码授权成功
Given 用户已打开平台登录页面
When 用户扫描二维码并在微信端确认授权
Then 系统获取用户微信OpenID
And 自动完成招聘者账号注册或登录
And 跳转至平台规则阅读页面

AC-1.1.2 异常流程：用户拒绝微信授权
Given 用户在微信授权弹窗中点击"拒绝"
When 授权回调返回拒绝状态
Then 系统提示"授权失败，请重新扫码或联系客服"
And 停留在登录页面，不创建账号

AC-1.1.3 异常流程：微信OpenID已绑定其他角色账号
Given 用户的微信OpenID已绑定为应聘者账号
When 用户尝试以招聘者身份登录
Then 系统提示"该微信已注册其他角色，是否切换？"
And 提供角色切换入口
```

|------|-----|
| **角色** | 招聘者 |
| **需求** | 我希望填写企业真实全名并设置对外展示的虚拟名称 |
| **价值** | 以便在完成平台合规登记的同时保护企业隐私 |
| **优先级** | P0 |
| **Story Points** | 3 |
| **前置依赖** | US-1.2 |

**验收标准（AC）：**

```gherkin
AC-1.3.1 正常流程：填写真实名和虚拟名
Given 用户处于企业信息填写页面
When 用户输入企业真实全名"北京某某科技有限公司"
And 输入虚拟名"某科技"并点击保存
Then 系统保存真实全名（仅平台后台可见）和虚拟名（对外展示）

AC-1.3.2 正常流程：关联已认证企业自动带入
Given 用户输入的企业名称匹配平台已认证企业库

AC-1.3.3 异常流程：虚拟名已被占用
Given 用户输入的虚拟名与已有用户重复
When 系统执行唯一性校验
Then 提示"该虚拟名已被使用，请更换名称"
And 高亮冲突字段引导修改

AC-1.3.4 异常流程：企业名称疑似虚假
Given 用户输入的企业名称与知名企业名称高度相似（如"华wei"）
When 系统风控引擎检测判定为疑似假冒
Then 标记该注册为"待人工审核"
And 提示"您的企业信息需要额外审核，预计1-3个工作日"
```

#### US-1.4 企业信息重复与冲突处理

| 属性 | 值 |
|------|-----|
| **角色** | 招聘者 |
| **需求** | 我希望在填写企业信息时，系统帮助我处理重复填写和假冒填写的情况 |
| **价值** | 以便避免信息冲突并确保企业信息的真实性和唯一性 |
| **优先级** | P1 |
| **Story Points** | 5 |
| **前置依赖** | US-1.3 |

**验收标准（AC）：**

```gherkin
AC-1.4.1 正常流程：检测到重复企业名称
Given 用户提交企业名称后系统执行查重
When 检测到已存在高度相似的企业名称（如仅差括号类型）
Then 展示"发现相似企业名称"列表
And 提供"确认是同一企业-申请关联"和"确认不同企业-继续注册"选项

AC-1.4.2 正常流程：用户确认同一企业并关联
Given 系统展示了相似企业列表
When 用户选择"确认是同一企业"
Then 系统向已有企业管理员发送关联申请
And 当前用户进入"待关联确认"状态

AC-1.4.3 异常流程：疑似假冒企业
Given 系统风控检测到企业名称与知名企业高度相似
When 置信度超过阈值
Then 自动标记为"疑似假冒"状态
And 触发人工审核流程
And 提示用户"您的企业信息需要人工核实，请准备相关证明材料"

AC-1.4.4 异常流程：用户申诉误判
Given 企业被标记为"疑似假冒"但实际为合法企业
When 用户点击"申诉"并上传营业执照等证明材料
Then 系统将申诉工单提交至人工审核队列
And 通知用户"申诉已提交，预计2个工作日内处理"
```

## 10. 风险与开放问题

### 10.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 微信授权接口变更 | 影响两端注册流程 | 封装授权层，做好接口适配 |
| 消息实时性要求高 | 消息延迟影响体验 | 采用WebSocket长连接 + 离线消息队列 |
| 内容审核准确性 | 误判影响用户体验 | 人工审核 + 机审双重机制 |
| 岗位模板库冷启动 | 初期模板覆盖率不足 | 优先覆盖Top 50热门岗位 |

### 10.2 业务风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 虚假企业信息 | 平台公信力受损 | 多级认证 + 举报机制 |
| 招聘者/应聘者比例失衡 | 匹配效率低 | 运营侧控制两端获客节奏 |
| 隐私信息泄露 | 用户信任危机 | 虚拟名机制 + 权限管控 |

### 10.3 开放问题（待决策）

| 编号 | 问题 | 待决策人 | 建议 |
|------|------|----------|------|
| Q-001 | 虚拟名是否允许重复？如"张先生"多人使用 | 产品经理 | 允许重复但添加编号区分 |
| Q-002 | 岗位审核时长SLA如何设定？ | 运营负责人 | 建议24小时内完成 |
| Q-003 | 消息是否支持撤回功能？ | 产品经理 | MVP暂不支持，二期考虑 |
| Q-004 | 数据统计的数据保留期限？ | 技术负责人 | 建议保留90天明细，1年汇总 |
| Q-005 | 应聘者信息补充是否为强制要求？ | 产品经理 | 建议渐进式引导，非强制 |
