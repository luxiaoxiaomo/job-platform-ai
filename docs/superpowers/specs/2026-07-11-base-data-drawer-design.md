# 基础数据新增与编辑抽屉设计

## 背景

标准职位库和标签库当前把新增、编辑表单直接放在列表上方。字段较多时会压缩列表空间，也难以清晰区分浏览状态和编辑状态。

用户确认改为抽屉交互：列表页保持数据浏览，新增和编辑在右侧抽屉内完成。

## 方案对比

### 方案 A：独立二级路由页面

- 优点：URL 可分享，页面空间充足。
- 缺点：新增、编辑会离开列表上下文，操作链路更长。

### 方案 B：右侧抽屉（采用）

- 优点：保留列表上下文，新增和编辑入口一致，操作完成后可立即看到刷新结果。
- 缺点：需要处理遮罩、脏数据确认和移动端宽度。

### 方案 C：详情页切换编辑模式

- 优点：详情和编辑关系紧密。
- 缺点：新增仍需单独入口，详情展示与表单职责混合。

## 页面结构

### 标准职位库

列表页只保留：

- 标题和总数。
- 右上角「新增标准职位」按钮。
- 标准职位表格。
- 「查看详情」「编辑」「启用 / 停用」操作。

移除列表顶部的内嵌新增、编辑表单。

点击「新增标准职位」或「编辑」后，从页面右侧打开统一抽屉。抽屉宽度在桌面端为 560 px；视口宽度小于 768 px 时占满屏幕。

### 标签库

列表页只保留：

- 标题和总数。
- 右上角「新增标签」按钮。
- 标签表格。
- 「查看详情」「编辑」「启用 / 停用」操作。

移除列表顶部的内嵌新增、编辑表单。新增和编辑共用标签抽屉。

## 抽屉组成

抽屉包含以下区域：

1. 固定头部：标题、关闭按钮。
2. 可滚动表单区域。
3. 固定底部：取消、保存按钮。

新增模式标题分别为「新增标准职位」「新增标签」。编辑模式标题分别为「编辑标准职位」「编辑标签」。

保存期间禁用提交按钮并显示「保存中...」，防止重复提交。

## 表单字段

### 标准职位

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 标准名称 | 是 | 去除首尾空格后提交 |
| 分类 | 是 | 去除首尾空格后提交 |
| 别名 | 否 | 使用逗号分隔，提交时转换为数组并移除空值 |
| 说明 | 否 | 空字符串转换为 `null` |
| 状态 | 是 | `active` 或 `inactive` |

### 标签

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 标签名称 | 是 | 去除首尾空格后提交 |
| 分类 | 是 | 例如 `skill`、`industry` |
| 父级标签 | 否 | 编辑时排除当前标签，防止选择自身 |
| 颜色 | 否 | 使用颜色输入和十六进制文本值联动 |
| 排序 | 否 | 非负整数，默认值为 0 |
| 说明 | 否 | 空字符串转换为 `null` |
| 状态 | 是 | `active` 或 `inactive` |

## 数据流

### 新增

1. 点击列表页右上角新增按钮。
2. 使用默认值打开抽屉。
3. 前端校验必填字段。
4. 调用创建 API。
5. 成功后关闭抽屉、显示成功提示并刷新对应列表。
6. 失败时保留表单内容，在抽屉内展示错误。

### 编辑

1. 点击行内「编辑」。
2. 抽屉进入加载状态，并通过详情 API 获取最新数据。
3. 数据加载成功后填充表单。
4. 保存时调用更新 API。
5. 成功后关闭抽屉、显示成功提示并刷新列表。
6. 加载或保存失败时保留抽屉，并展示可读错误。

## 关闭与脏数据保护

- 表单未发生修改时，点击关闭按钮、取消按钮、遮罩或按 `Esc` 可直接关闭。
- 表单发生修改后，上述关闭行为需要二次确认。
- 保存成功后直接关闭，不再触发二次确认。

## 组件边界

- `BaseData`：负责列表加载、抽屉开关状态和保存成功后的刷新。
- `AdminBaseDataDrawer`：负责遮罩、布局、关闭确认和底部操作区。
- `StandardPositionForm`：负责标准职位字段与 payload 转换。
- `TagLibraryForm`：负责标签字段、父级选项和 payload 转换。

抽屉及表单放入独立模块，避免继续扩大 `AdminApp.jsx`。

## 错误处理

- 必填字段缺失时在对应字段下展示错误，不发送 API 请求。
- 编辑详情加载失败时显示错误状态和「重试」按钮。
- API 保存失败时保留用户输入，并显示后端错误信息。
- 父级标签列表加载失败时允许保存其他字段，但父级选择不可用并显示提示。

## 验收标准

- [ ] 标准职位列表页不再展示内嵌新增、编辑表单。
- [ ] 标签列表页不再展示内嵌新增、编辑表单。
- [ ] 两个列表页都能通过右上角按钮打开新增抽屉。
- [ ] 两个列表页的行内「编辑」都能打开并正确填充编辑抽屉。
- [ ] 新增和编辑成功后抽屉关闭，列表立即刷新。
- [ ] 编辑抽屉使用详情 API 的最新数据，而不是只依赖列表快照。
- [ ] 标签不能把自身设置为父级。
- [ ] 表单存在未保存修改时，关闭抽屉需要确认。
- [ ] 标准职位和标签详情页保持可用。
- [ ] ESLint、Vitest、生产构建和真实浏览器流程通过。

## 测试策略

先新增浏览器回归，证明当前内嵌表单行为不符合设计。实现后验证：

1. 新增标准职位并在列表中看到结果。
2. 编辑标准职位并验证最新字段。
3. 新增带父级的标签。
4. 编辑标签并验证自身不出现在父级选项中。
5. 修改字段后关闭抽屉，确认脏数据保护生效。
6. 重新执行基础数据详情页回归。
7. 执行前端 lint、Vitest 和生产构建。

## 非目标

- 不修改后端 API 和数据模型。
- 不改变「启用 / 停用」快捷操作。
- 不增加批量导入、批量编辑或删除能力。
- 不重做管理后台整体视觉体系。
