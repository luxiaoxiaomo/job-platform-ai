## 1. 架构设计概述

### 1.1 设计目标

本平台采用微服务架构，以支撑"AI增强型空岗信息发布对接"核心链路。架构设计围绕以下目标展开：高可用（系统可用率 >= 99.5%）、可扩展（模块独立部署、水平扩容）、AI原生（AI服务层独立、支持热插拔和降级）、安全合规（敏感数据加密、RBAC权限、审计日志）。

## 2. 微服务拆分设计

### 2.1 服务清单

| 服务名 | 职责 | 核心接口 | 依赖 |
|--------|------|---------|------|
| **user-svc** | 用户注册/认证/资料管理、企业信息管理、微信OAuth对接 | /api/users, /api/enterprises | MySQL, Redis, OCR服务 |
| **job-svc** | 岗位CRUD、草稿管理、发布审核流转、岗位状态机 | /api/jobs, /api/jobs/drafts | MySQL, Redis, MQ(审核事件) |
| **msg-svc** | 留言收发、对话管理、消息审核、联系方式交换 | /api/messages, /api/conversations | MongoDB, Redis, MQ(推送通知) |
| **push-svc** | 微信模板消息推送、订阅匹配、推送调度 | /api/subscriptions, /api/push | MySQL, Redis, RabbitMQ |
| **review-svc** | 企业资质审核、岗位内容审核、审核队列管理 | /api/reviews | MySQL, RabbitMQ, AI内容安全 |
| **search-svc** | 岗位搜索、人才搜索、搜索排序 | /api/search | Elasticsearch, Milvus |
| **stats-svc** | 数据统计、埋点采集、报表生成、**浏览量穿透(访客明细)、全岗位聚合看板、JD吸引力分析数据** | /api/stats, /api/events, /api/jobs/{id}/visitors | MySQL, ClickHouse(分析) |
| **cs-svc** | 智能客服、知识库管理、人工转接 | /api/chatbot | MongoDB, LLM服务 |
| **talent-svc** | **人才池(按人聚合)、候选人列表、人才详情、团队协作备注、双向标签、跟进提醒规则引擎** | /api/talents, /api/talents/{id}/notes, /api/follow-ups | MySQL, 聚合 user/msg/stats-svc |
| **admin-svc** | 管理后台聚合API、用户管理、基础数据维护 | /api/admin/* | 聚合调用各业务服务 |
| **ai-gateway** | AI模型统一调度、路由、降级、计量、Prompt管理 | 内部gRPC/HTTP | 所有AI服务 |

### 2.2 服务通信模式

```
同步调用 (OpenFeign):
  user-svc ──► ai-gateway (OCR识别)
  job-svc  ──► ai-gateway (内容审核/JD生成)
  msg-svc  ──► ai-gateway (智能回复/情感分析)
  admin-svc ──► user-svc / job-svc / review-svc

异步消息 (RabbitMQ):
  job-svc  ──[job.submitted]──► review-svc (触发审核)
  review-svc ──[review.approved]──► job-svc (更新状态) + push-svc (触发推送)
  push-svc ──[push.matched]──► 订阅用户推送
  msg-svc  ──[message.new]──► push-svc (消息通知)
  user-svc ──[user.registered]──► stats-svc (埋点记录)
  ai-gateway ──[ai.call.logged]──► stats-svc (AI用量统计)

  【V1.1 新增】
  talent-svc ──► user-svc / msg-svc / stats-svc (聚合人才数据)
  talent-svc ──► ai-gateway (选人标准打分/面试准备/JD吸引力)
  stats-svc ──► talent-svc (访客明细转人才画像)
```

## 3. 数据库设计

### 3.1 数据库分布策略

| 数据库 | 存储内容 | 理由 |
|--------|---------|------|
| **MySQL** | 用户、企业、岗位、订阅、审核记录、系统配置 | 强一致性、事务支持、关系查询 |
| **Redis** | Session、验证码、岗位浏览计数、消息未读数、限流计数器 | 高性能KV、过期策略、原子操作 |
| **MongoDB** | 消息对话、操作日志、AI调用日志、客服会话 | 文档灵活、写入性能高、无需固定Schema |
| **Elasticsearch** | 岗位全文索引、人才搜索索引 | 全文检索 + 聚合分析 |
| **Milvus** | 岗位Embedding向量、用户画像向量 | 高维向量近似搜索(ANN) |
| **MinIO/OSS** | 营业执照、名片、简历附件、头像 | 二进制文件存储 |

### 5.5 选人标准匹配引擎（★本轮新增，对应语音核心诉求）

> **背景**：2026-06-03 评审中产品反复强调——当前 AI 匹配只基于"岗位标签"，但招聘者真正需要的是"选人标准"。即从**任职要求**中提炼出可量化的评分维度，每个维度有明确的打分规则，AI 据此对候选人逐项打分。这是匹配引擎从"标签相似度"升级为"标准化评分"的关键，也是后续商业化收费点（匹配功能按调用计费）。

```
选人标准匹配流程:

  ① 岗位发布/编辑时：
     任职要求文本
          │
          ▼
  ┌──────────────────────────┐
  │ AI 维度提炼 (criteria-extract) │
  │ LLM 按预设框架从任职要求中     │
  │ 提炼评分维度 + 权重 + 打分规则 │
  │ 框架(后台配置, 作为Prompt):    │
  │  · 学历: 本科80/硕士90/博士100 │
  │  · 经验: 1-3年60/3-5年80/5-8年90/8年+95 │
  │  · 核心技能: 命中数加权        │
  │  · 稳定性 / 软素质 / 证书...   │
  └──────────────────────────┘
          │
          ▼
  存入 job_selection_criteria 表
  (招聘者可在前台编辑维度/权重/规则)

  ② 候选人匹配时：
     候选人画像(简历解析后的结构化数据)
          │
          ▼
  ┌──────────────────────────┐
  │ 按标准逐维度打分 (score-by-criteria) │
  │ for 每个维度:                │
  │   分数 = 打分规则.match(候选人该维度值) │
  │ 综合分 = Σ(维度分 × 权重)     │
  └──────────────────────────┘
          │
          ▼
  返回: 综合匹配度 + 分项得分(雷达图)
        + 可解释说明(每维度为何得此分)
```

**关键设计要点：**

| 要点 | 说明 |
|------|------|
| **维度是动态的** | 不同岗位/行业维度不同，后台维护"提炼框架"作为 Prompt，AI 据此提炼，而非硬编码固定维度 |
| **打分标准可配置** | 招聘者可在前台编辑每个维度的权重和打分规则（如"经验"各档位分数），覆盖 AI 默认值 |
| **匹配可解释** | 前端匹配度数字可穿透展开，展示分项得分（雷达图）+ 文字说明"为什么 80%"——已在原型实现 |
| **冷启动降级** | 一期数据不足时，"先有这个能力即可"——允许 AI 粗略打分，标注"仅供参考"，准确度后续迭代 |
| **商业化挂钩** | 匹配/筛选功能为收费点，按调用次数计费（提前几天预付），需在 ai-gateway 计量 |

> ⚠️ **实施边界**：选人标准的"提炼框架"应在管理后台/PC 端配置（涉及保险额度等复杂规则填写），不在手机端操作。手机端只展示提炼结果和匹配度。该模块依赖简历结构化数据（二期 AI 简历解析），一期可先做"标准提炼 + 粗略打分"的框架，标准数据后续补全。

### 6.4 数据安全方案

| 安全措施 | 实现方式 | 覆盖范围 |
|---------|---------|---------|
| **传输加密** | 全链路HTTPS/TLS 1.3 | 所有API通信 |
| **敏感数据加密** | AES-256-GCM + KMS密钥管理 | 真实姓名、手机号、信用代码、邮箱 |
| **数据脱敏** | AI调用前PII去标识化 | 发送给第三方AI API的用户数据 |
| **访问控制** | RBAC + JWT + API签名 | 所有接口 |
| **限流防护** | 令牌桶算法(APISIX) | 公开API + AI功能调用 |
| **审计日志** | 操作日志180天留存 | 管理后台操作、审核记录 |
| **数据备份** | 每日全量 + 实时增量 | MySQL, MongoDB, Redis |
| **灾备恢复** | RTO<=4h, RPO<=1h | 核心数据库 |
| **AI内容标注** | 所有AI生成内容标注"AI生成" | JD代写、智能回复、推荐摘要 |
