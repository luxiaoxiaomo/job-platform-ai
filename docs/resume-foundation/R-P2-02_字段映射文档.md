> 目标: 把 STIC/V1.3 的字段**压缩**成空岗平台 P2 真正要落库和展示的字段，不照搬大宽表。

## 0. 设计原则（与 Codex P2 任务对齐）

1. **不照搬 STIC 大宽表**（STIC `hhr_ta_basic_info` 有 60+ 字段），只保留 P2 真正需要的。
2. **P2 范围**：原文 → 可确认、可追溯、可投影到明细表的结构化结果。不做 AI 筛选、不做向量匹配。
3. **隐私取舍（空岗平台差异化）**：身份证、婚育、户籍、民族、政治面貌等敏感字段**不纳入** P2，守住"虚拟名 + 隐私保护"定位。
4. **分级落库**：高置信度/已确认字段才投影到明细表；低置信度先留在 `resume_structured_profiles` JSON 里待确认。
5. **每条明细记录**都带 `seeker_id` + `upload_id` + `parse_run_id`（可追溯到哪次解析）。

### 字段标注说明

| 标注 | 含义 |
|------|------|
| **优先级** | P2必填 / P2可选 / P3后置 |
| **需确认** | 是=低置信度需用户确认才回写；否=可直接展示 |
| **可筛选** | 是=后续（B阶段企业筛选/人岗匹配）会用作筛选维度 |
| **展示标签** | 前端 UI 上的中文标签 |

## 7. 汇总：P2 第一版落库范围

### 6 张明细表 + 1 张 JSON 源表

| 表 | P2必填字段数 | 说明 |
|----|------------|------|
| `resume_structured_profiles` | (JSON源) | Codex 已规划，解析原始结果 + 置信度 |
| `resume_basic_infos` | 6 必填 | 姓名/学历/工作年限 + 追溯三件套 |
| `resume_educations` | 6 必填 | 学校/专业/学历 + 追溯 |
| `resume_work_experiences` | 7 必填 | 公司/职位/起止 + 追溯 |
| `resume_projects` | 4 必填 | 项目名 + 追溯 |
| `resume_skills` | 4 必填 | 技能名 + 追溯 |
| `resume_certificates` | 4 必填 | 证书名 + 追溯 |

### 关键取舍总结

1. **裁字段**：STIC basic_info 60+ 字段 → 我们 basic_infos 约 10 个业务字段。
2. **去隐私**：身份证/婚育/户籍/民族/政治面貌/年龄(直接项) 全部不纳入。
3. **合并表**：语言证书并入 certificates，P2 不单建 languages 表。
4. **后置项**：院校层级、岗位级别、行业、技能分类等"需字典支撑"的 → P3。薪资匹配 → P3。
5. **可追溯**：每张明细表都带 seeker_id + upload_id + parse_run_id。
6. **先确认后落库**：标"需确认=是"的字段，低置信度时先留 JSON，用户确认才写明细表 + 回写 seeker_profiles。

## 8. 给 Codex 的接口期望（供 P2 API contract 参考）

前端确认页（R-P2-04）需要的接口形态：

```
GET /api/v1/resumes/me/parse-runs/{id}/structured
返回：{
  basic: {name, gender, phone, email, education, work_years, current_city, target_position,
          _confidence: {字段:0~1}, _confirmed: bool},
  educations: [{school_name, major, degree, start_date, end_date, _confidence}],
  work_experiences: [{company_name, position_name, start_date, end_date, job_content, _confidence}],
  projects: [...],
  skills: [{skill_name, skill_level, _confidence}],
  certificates: [{cert_name, cert_type, _confidence}]
}

PUT /api/v1/resumes/me/structured/confirm
入参：用户确认/修改后的字段 → 投影到明细表 + 回写 seeker_profiles + 写 change_logs
```

关键约定：
- 每个字段带 `_confidence`（0~1），前端按阈值显示"待确认/低置信度"视觉。
- 确认是**字段级**的，用户可逐项采纳/修改。
- 确认前不覆盖 `seeker_profiles`。
