# 项目记忆与交接机制

## 定位

本机制用于约束 Codex、Claude 或其他协作者在同一仓库内交接时如何维护当前状态、历史经验和验证证据。

核心原则：

1. `docs/HANDOFF.json` 是当前状态 truth source。
2. PRD、验收记录、审计记录和协作文档是可读的解释层。
3. AhaDiff 是本地辅助记忆，用于从 diff/commit 中沉淀可检索经验，不替代 HANDOFF。

## 信息源分层

| 层级 | 文件/工具 | 作用 | 更新责任 |
| --- | --- | --- | --- |
| 当前事实源 | `docs/HANDOFF.json` | 当前焦点、任务状态、ready 信号、下一步归属 | 每次完成或阻塞任务时更新 |
| 产品与契约 | PRD、接口契约、任务包 | 定义范围、边界、接口、验收口径 | 新需求、范围变化或契约变化时更新 |
| 验收与审计 | `docs/acceptance/`、`docs/audit/`、`docs/operations/`、`docs/demo/` | 记录测试、演示、上线前检查、数据治理 | 运行验证或形成新流程时更新 |
| 协作说明 | `docs/collaboration/` | 解释多 AI 协作方式和历史决策 | 协作机制变化时更新 |
| 本地辅助记忆 | AhaDiff MCP/CLI | 从代码或文档 diff 生成 lesson、review cards、可检索证据 | 重要变更后按需运行 |

## 何时更新 HANDOFF

必须更新 `docs/HANDOFF.json` 的情况：

1. 一个任务从 todo/in_progress/review 进入 done 或 blocked。
2. 当前焦点变化，例如从 P3/R-P4-01 实施转入 P4 智能匹配规划。
3. 新增或关闭跨人/跨 AI 的待办信号。
4. 产生可执行的下一步任务，且需要另一个协作者接手。
5. 完成阶段性审计后，需要把已交付文档、验证证据和残余风险同步给下一个会话。

更新要求：

- `last_updated_by` 和 `last_updated_at` 必须同步更新。
- `current_focus` 用一句话描述当前真实状态，不写历史长叙述。
- `tasks[]` 只保留当前仍有交接价值的任务和关键已完成里程碑。
- `signals.pending_for_codex`、`signals.pending_for_claude` 必须与任务状态一致。
- 如果没有待接手工作，pending 数组必须为空。

## 何时更新 PRD、验收记录和协作文档

| 文档类型 | 更新触发 | 例子 |
| --- | --- | --- |
| PRD | 产品范围、用户、MVP、非范围、验收口径变化 | 新增 P4 智能匹配 MVP 表、调整 P3/P4 边界 |
| 接口契约 | API、权限、错误码、审计字段、数据依赖变化 | 新增 `/api/v1/matches/intelligent/*` 契约 |
| 任务包 | 前后端拆分、依赖、验证方式、回滚方式变化 | P4 backend/frontend/data/ops task package |
| 验收记录 | 执行或 dry-run 核心流程、记录缺陷、补充证据 | 核心业务闭环 12 步验收 |
| 审计记录 | 上线前技术体检、安全/权限/迁移/日志检查 | 预发布 audit、P0/P1/P2 blocker list |
| 协作文档 | 协作协议、交接机制、自动推进模式变化 | HANDOFF 与 AhaDiff 责任分层 |

规则：当前事实写入 HANDOFF；为什么这样做、怎么验证、失败怎么修复，写入对应 Markdown 文档。

## AhaDiff 使用规则

### 当前可用状态

本次检查结果：

- AhaDiff MCP 可用：`get_stats` 返回 `total_runs=0`、`total_cards=0`、`total_concepts=0`。
- AhaDiff MCP 可用：`list_runs` 返回空数组。
- `ahadiff` CLI 当前不在 PowerShell PATH，`ahadiff --version` 和 `ahadiff doctor` 返回 CommandNotFound。

因此当前默认使用 AhaDiff MCP 查询本地记忆；需要创建新 lesson 时，先安装或暴露 CLI，再执行 learn 命令。

### 何时运行 AhaDiff

建议在以下节点运行：

1. 完成一个有实质 diff 的开发任务后。
2. 合并或交接一个跨模块改动前。
3. 修复 P0/P1 缺陷后，需要把根因、证据和回归验证沉淀为 lesson。
4. 完成阶段性文档/规划后，需要让后续会话快速检索“为什么这样设计”。
5. 收到 review 反馈后，需要把高价值经验转成复习卡片。

不建议把 AhaDiff 用作普通任务状态源，也不把它当作验收通过依据。验收仍以测试、构建、审计文档和 HANDOFF 为准。

### 如何使用 AhaDiff MCP

常用 MCP 查询：

- `get_stats`：确认本地记忆规模和最近运行情况。
- `list_runs`：查看最近 run。
- `get_run_summary`：读取某次 run 的分数和 lesson 摘要。
- `ask_lesson`：围绕某次 run 查询经验片段和证据。
- `search`：跨 concepts、result_events、cards、graph nodes 检索历史知识。
- `list_due_cards`：查看需要复习的 cards。

使用要求：

1. 查询结果只能作为辅助上下文，不能覆盖仓库文件的当前事实。
2. 如果 AhaDiff 与 HANDOFF 冲突，以 HANDOFF 和当前文件内容为准，并在 HANDOFF 或相关文档中纠正状态。
3. 引用 AhaDiff 结论时，标注 run id 和 claim/evidence 状态。
4. 对安全、权限、数据删除、上线判断，不使用 AhaDiff 单独做最终依据。

### CLI 可用后的建议命令

在 CLI 可用并确认隐私边界后使用：

```powershell
cd D:\AIposition
git status --short
ahadiff learn --unstaged --include-untracked
ahadiff review
```

如果只想学习 staged changes：

```powershell
ahadiff learn --staged
```

如果只想学习最近一次提交：

```powershell
ahadiff learn --last
```

注意：远程 provider 配置后，diff 内容可能发送给模型服务。涉及密钥、客户数据或敏感生产配置时，先排除敏感文件或仅使用本地允许的范围。

## 交接流程

### 开工前

1. 读取 `docs/HANDOFF.json`。
2. 检查 `signals.pending_for_<agent>` 和 `current_focus`。
3. 读取相关 PRD、契约、验收或审计文档。
4. 如任务涉及历史经验，使用 AhaDiff MCP `search` 或 `list_runs` 查本地记忆。
5. 明确本轮要改的文件范围和验证方式。

### 收工前

1. 更新任务产物文档或代码。
2. 运行与变更风险匹配的验证。
3. 更新相关 PRD/验收/审计/协作文档。
4. 更新 `docs/HANDOFF.json`，同步当前焦点、任务状态、验证证据和 pending 信号。
5. 对重要 diff，运行或计划 AhaDiff lesson。
6. 记录无法完成的 P0/P1 风险；若存在未解 P0/P1，不得把目标标记为完成。

## 冲突处理

| 冲突 | 处理规则 |
| --- | --- |
| HANDOFF 与 Markdown 叙述冲突 | 先读当前代码/文档证据，修正 HANDOFF；必要时补 changelog |
| AhaDiff 记忆与当前文件冲突 | 当前文件优先；AhaDiff 标为历史记忆 |
| PRD 与实现冲突 | 若是未实现需求，写入 backlog/repair task；若是 PRD 过期，更新 PRD |
| 验收记录与测试结果冲突 | 以最新可复现测试/构建为准，并更新验收记录 |
| 两个 agent 同时改同一文件 | 停止自动推进，先合并状态和职责边界 |
