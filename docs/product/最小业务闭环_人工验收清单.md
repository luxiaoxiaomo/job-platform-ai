# 最小业务闭环人工验收清单

本文用于验证 PRD 一期最小闭环：

```text
招聘者发布岗位 -> 管理员审核岗位 -> 求职者看到岗位 -> 求职者留言或投递 -> 招聘者处理线索 -> 双方完成有效对接
```

## 1. 验收前准备

### 服务地址

```text
前端：http://127.0.0.1:5174
后端：http://127.0.0.1:8003
```

如果后端不是 reload 模式，改动后需要重启后端。

### 推荐测试账号

优先使用 `docs/collaboration/本地测试账号.md` 里的账号。若账号数据被清空，可重新注册：

```text
招聘者：任意 recruiter 角色手机号
求职者：任意 seeker 角色手机号
管理员：admin 角色账号
```

招聘者发布岗位前，必须先完成企业认证并由管理员审核通过。

## 3. 12 步人工验收

### Step 1：招聘者登录或注册

入口：

```text
/#/login
```

预期：

```text
登录后可进入招聘者端 /#/recruiter/jobs
```

### Step 2：招聘者完成企业认证

入口：

```text
/#/recruiter/register
```

预期：

```text
提交认证后状态为 pending。
```

如果已经认证通过，可跳过本步。

### Step 3：管理员审核企业认证

入口：

```text
/#/admin
```

操作：

```text
进入审核管理，找到企业认证记录，点击通过。
```

预期：

```text
招聘者端企业认证状态变为 approved，可发布岗位。
```

### Step 4：招聘者创建新岗位

入口：

```text
/#/recruiter/job/create
```

预期：

```text
提交成功后，岗位进入 pending 待审核状态。
招聘者 /#/recruiter/jobs 能看到该岗位。
```

### Step 5：管理员审核岗位

入口：

```text
/#/admin
```

操作：

```text
进入审核管理，找到待审核岗位，点击通过。
```

预期：

```text
岗位状态变为 active。
```

接口排查：

```text
GET /api/v1/jobs/admin?status=pending
POST /api/v1/jobs/admin/{job_id}/review
```

### Step 6：求职者看到公开岗位

入口：

```text
/#/seeker/home
```

预期：

```text
求职者首页岗位列表展示刚审核通过的岗位。
```

接口排查：

```text
GET /api/v1/jobs/public
```

### Step 7：求职者进入岗位详情

入口：

```text
/#/seeker/job/{job_id}
```

预期：

```text
岗位详情展示同一个真实岗位的数据。
```

接口排查：

```text
GET /api/v1/jobs/public/{job_id}
字段说明：公开岗位详情每打开一次，`view_count` 会递增；求职者对岗位发起留言咨询后，`conversation_count` 会按岗位聚合递增；招聘者岗位列表展示这两个真实数字。
```

### Step 8：求职者发起留言咨询

操作：

```text
在岗位详情点击“留言咨询”。
```

预期：

```text
进入真实聊天页。
不会自动发送默认消息。
求职者可以手动发送消息。
```

接口排查：

```text
POST /api/v1/messages/conversations/open
POST /api/v1/messages/conversations/{conversation_id}/messages
```

### Step 9：招聘者看到并回复留言

入口：

```text
/#/recruiter/jobs?tab=messages
```

预期：

```text
招聘者消息列表出现该会话。
招聘者进入会话后可以回复。
```

接口排查：

```text
GET /api/v1/messages/conversations
GET /api/v1/messages/conversations/{conversation_id}
```

### Step 10：求职者立即投递

入口：

```text
/#/seeker/apply/{job_id}
```

预期：

```text
上传或选择简历后，提交投递成功。
重复投递同一岗位会被后端拒绝。
```

接口排查：

```text
POST /api/v1/resumes/me/upload
POST /api/v1/applications
```

### Step 11：双方查看投递记录

求职者入口：

```text
/#/seeker/applications
```

预期：

```text
列表中能看到真实投递。
点击投递记录后进入真实投递详情。
详情 URL 形如：/#/seeker/applications?applicationId={application_id}
```

招聘者入口：

```text
/#/recruiter/jobs?tab=talent
/#/recruiter/talent
/#/recruiter/applications/{application_id}
```

预期：

```text
招聘者能看到该岗位收到的真实投递。
投递详情展示简历快照、状态时间线、沟通状态和联系方式交换状态。
招聘者可以更新状态：已查看、邀面、拒绝、录用。
```

接口排查：

```text
GET /api/v1/applications/me
GET /api/v1/applications/me/{application_id}
GET /api/v1/applications/recruiter
GET /api/v1/applications/recruiter/{application_id}
POST /api/v1/applications/{application_id}/status
```

### Step 12：双方交换联系方式

入口：

```text
聊天页
```

操作：

```text
一方点击请求交换联系方式。
另一方点击同意。
```

预期：

```text
双方聊天详情里 contact_exchange.status 为 accepted。
招聘者能看到求职者联系方式。
求职者能看到招聘者联系方式。
聊天里手打手机号、邮箱、微信号会被脱敏。
```

接口排查：

```text
POST /api/v1/messages/contact-exchanges
POST /api/v1/messages/contact-exchanges/{exchange_id}/review
GET /api/v1/messages/conversations/{conversation_id}
```

### Step 13：查看有效对接统计

招聘者入口：

```text
/#/recruiter/stats
```

管理员入口：

```text
/#/admin
```

预期：

```text
招聘者数据统计页展示当前招聘者的成功对接、待确认交换、已拒绝交换和交换请求总数。
管理员后台首页展示全平台有效对接汇总。
统计口径：contact_exchange.status = accepted 计为一次有效对接。
```

接口排查：

```text
GET /api/v1/messages/contact-exchanges/stats/summary
GET /api/v1/applications/recruiter/stats/summary
GET /api/v1/applications/admin/stats/summary
```

### Step 14：查看招聘漏斗真实数据
招聘者入口：

```text
/#/recruiter/funnel
```

预期：
```text
招聘漏斗页展示当前招聘者的真实岗位浏览数、咨询数、投递数、已处理数、面试邀约数和录用数。
选择单个岗位后，浏览数和咨询数按该岗位聚合；投递、处理、邀约、录用按该岗位的真实投递记录聚合。
联系方式交换统计作为招聘者全局辅助指标展示。
```

接口排查：
```text
GET /api/v1/jobs/me
GET /api/v1/applications/recruiter
GET /api/v1/messages/contact-exchanges/stats/summary
```

### Step 15：查看访客穿透真实数据
招聘者入口：

```text
/#/recruiter/job/visitors/{job_id}
```

触发方式：
```text
求职者登录后打开公开岗位详情：/#/seeker/job/{job_id}
匿名用户打开岗位详情只累计 total view_count，不进入访客名单。
```

预期：
```text
招聘者能看到该岗位的真实总浏览数、已登录独立访客数、高意向访客数和已咨询人数。
访客列表按求职者聚合展示：浏览次数、首次/最近浏览时间、是否已咨询、是否已投递、高意向标识和意向分。
招聘者只能查看自己发布岗位的访客数据。
```

接口排查：
```text
GET /api/v1/jobs/public/{job_id}
GET /api/v1/jobs/me/{job_id}/visitors
```

## 4. 验收通过标准

满足以下条件即可认为一期主业务闭环打通：

```text
1. 岗位从招聘者发布到管理员审核通过，再到求职者可见。
2. 求职者能对真实岗位留言。
3. 招聘者能看到并回复真实留言。
4. 求职者能对真实岗位投递。
5. 招聘者能看到并处理真实投递。
6. 求职者能查看自己的投递进度。
7. 双方能在聊天中完成联系方式交换。
8. 后端闭环测试和前端 build 均通过。
```

## 6. 2026-06-19 求职者侧三件套更新

本轮已把求职者侧“浏览历史、收藏、订阅”从 mock 推进为真实接口：

```text
浏览历史：
- 登录求职者打开公开岗位详情后，后端写入 job_visits。
- 求职者可通过 /#/seeker/history 查看真实浏览记录。
- API: GET /api/v1/jobs/seeker/history

收藏：
- 新增 job_favorites 表，同一求职者对同一岗位幂等收藏。
- 求职者可通过 /#/seeker/favorites 查看和取消收藏。
- API:
  POST /api/v1/jobs/seeker/favorites/{job_id}
  GET /api/v1/jobs/seeker/favorites
  DELETE /api/v1/jobs/seeker/favorites/{job_id}

订阅：
- 新增 job_subscriptions 表，支持关键词、城市、薪资下限/上限和启停状态。
- /#/seeker/home 的“订阅”tab 已接真实列表、创建和启停。
- API:
  POST /api/v1/jobs/seeker/subscriptions
  GET /api/v1/jobs/seeker/subscriptions
  PUT /api/v1/jobs/seeker/subscriptions/{subscription_id}
  DELETE /api/v1/jobs/seeker/subscriptions/{subscription_id}
```
