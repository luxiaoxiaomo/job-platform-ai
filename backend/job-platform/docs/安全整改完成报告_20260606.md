## 完成清单

### ✅ 1. 测试环境安全

**问题**：
- 使用`DATABASE_URL.replace()`推导测试库
- 无测试库名校验，存在误操作风险

**修复**：
- 新增`TEST_DATABASE_URL`配置项（`.env`和`config.py`）
- `conftest.py`增加强制校验：测试库名必须包含`_test`
- `drop_all()`前二次校验，拒绝操作非测试库

**修改文件**：
- `app/core/config.py` - 新增TEST_DATABASE_URL
- `tests/conftest.py` - 安全校验逻辑
- `.env` - 新增TEST_DATABASE_URL配置
- `.env.example` - 同步更新

---

### ✅ 2. 拆出PHONE_HASH_SECRET

**问题**：
- `hash_phone()`复用`JWT_SECRET_KEY`
- 密钥职责混乱，风险扩散

**修复**：
- 新增`PHONE_HASH_SECRET`独立配置
- `hash_phone()`改用`settings.PHONE_HASH_SECRET`
- 生产环境强制校验不能为默认值
- `.env.example`增加生成指引

**修改文件**：
- `app/core/config.py` - 新增PHONE_HASH_SECRET配置和校验
- `app/utils/phone_hash.py` - 改用独立密钥
- `.env` - 添加PHONE_HASH_SECRET
- `.env.example` - 添加说明和生成方法

**密钥生成方法**：
```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

---

### ✅ 3. 修正Alembic迁移

**问题**：
- phone_hash字段在第二个迁移中添加（应该在初始表就有）
- unique constraint未命名
- upgrade/downgrade未充分验证

**修复**：
- 删除旧迁移，重新生成单一初始迁移
- phone_hash在create_table时直接包含
- 命名所有约束：`pk_users`, `uq_users_phone_hash`
- 命名所有索引：`idx_users_phone_hash`, `idx_users_role`, `idx_users_status`
- 增加迁移说明文档：适用场景、注意事项
- ENUM类型使用DO块实现幂等性

**修改文件**：
- `alembic/versions/421bc078883c_initial_schema_with_phone_hash.py` - 新的单一初始迁移

**迁移说明**：
- 适用场景：全新部署
- 如有旧数据：需手动迁移phone_hash字段
- 验证命令：`alembic upgrade head` / `alembic downgrade -1`

---

### ✅ 4. 修复验证码限流

**问题**：
- 非原子操作（GET + INCR竞态条件）
- 仅手机号维度，无IP限流
- Redis异常时无条件fail-open

**修复**：
- 新建`rate_limiter_v2.py`使用Lua脚本保证原子性
- 增加IP维度限流（每分钟5号码、每小时20号码）
- `fail_open`参数可控，短信场景默认`False`
- `auth.py`改用新限流器，获取客户端IP

**新增文件**：
- `app/utils/rate_limiter_v2.py` - 原子限流器

**修改文件**：
- `app/api/v1/auth.py` - 使用新限流器+IP维度

**限流规则**：

| 维度 | 每分钟 | 每小时 | 每天 |
|------|--------|--------|------|
| 手机号 | 1次 | 3次 | 10次 |
| IP | 5个号码 | 20个号码 | - |
