# 需求优先级排序报告：空岗信息发布对接平台（一期）

> **版本**：v1.0
> **日期**：2026-06-02
> **排序框架**：RICE（主）+ MoSCoW（辅）
> **团队规模**：5人（前端2 + 后端2 + 测试1）
> **Sprint周期**：2周/迭代

---

## 一、业务目标假设

| 假设项 | 说明 |
|--------|------|
| **MVP目标** | 快速上线验证市场，跑通"发布空岗 - 订阅匹配 - 沟通对接"核心闭环 |
| **核心关注** | 供需匹配效率（岗位与人才的连接速度和质量）、用户注册转化率 |
| **目标用户** | 招聘者（B端，中小企业为主）+ 应聘者（C端，蓝领/灵活用工为主） |
| **MVP预期MAU** | 约1000人（招聘者~150人，应聘者~850人），基于种子用户冷启动估算 |
| **技术约束** | 依托微信生态（服务号 + 微信认证），降低获客门槛 |
| **运营约束** | 一期上线后由运营人员手动辅助完成企业认证审核、费用结算等管理工作 |

## 二、RICE评分明细

> **评分标准说明**
> - **R（Reach）**：每月影响用户数，基于MVP阶段预估MAU~1000人估算
> - **I（Impact）**：0.25（极低）/ 0.5（低）/ 1（中）/ 2（高）/ 3（极高）
> - **C（Confidence）**：50%（低信心）/ 80%（中信心）/ 100%（高信心）
> - **E（Effort）**：人月（1人月 = 1人工作20个工作日）
> - **RICE Score** = (R x I x C) / E，数值越高优先级越高

## 七、决策记录

### 7.1 核心取舍决策

| 决策 | 取舍 | 理由 |
|------|------|------|
| **费用管理一期不做** | 舍弃在线支付，用线下/免费替代 | 资金合规复杂（支付牌照、对公账户），一期免费开放快速获客，验证匹配价值后再引入付费 |
| **会员管理一期不做** | 舍弃分级体系，运营手动标记 | 会员体系需要足够用户规模才有分级价值，一期重点是做大用户池 |
| **企业认证非强制** | 允许未认证企业发布（标"待认证"标签） | 降低招聘者发布门槛，加速供给侧冷启动；通过标记保护应聘者知情权 |
| **数据统计简版** | 仅做基础计数，不做深度分析 | 一期数据量小，深度分析ROI低，用后台SQL导出可满足运营需求 |
| **基础管理最小化** | 仅做字段设置和职位库，暂不做标签库/JD模板库 | 一期岗位类型有限，人工辅助运营即可，二期根据数据积累再标准化 |

### 7.2 争议需求分析

| 争议需求 | 争议点 | 最终决策 | 决策依据 |
|---------|--------|---------|---------|
| **C04 查看职位完整信息（需补充个人信息）** | 补充4类信息门槛是否过高导致用户流失？ | **保留，但采用分步引导** | 这是平台的"价值交换"核心机制（用信息换详情），且补充信息直接提升匹配质量。通过分步引导（先基本信息，后可选补充）降低流失风险 |
| **D04 企业认证发布** | 是否一期强制认证？ | **不强制，改为Should** | 强制认证会大幅提高招聘者发布门槛，不利于冷启动。采用"鼓励认证+待认证标签"折中方案 |
| **P01 微信服务号对接** | 工作量2人月是否可压缩？ | **拆分为两阶段** | Sprint 1完成OAuth+基础接口（1.5人月），Sprint 2补齐模板消息推送（0.5人月），避免阻塞注册流程 |
| **C05/D08 转发推荐** | 是否一期做社交裂变？ | **C05放Sprint 4，D08延后** | 转发招聘职位有自然增长价值且工作量小；转发应聘者需求频次低，一期可人工处理 |

## 八、风险与依赖

| 风险项 | 影响 | 缓解措施 |
|--------|------|---------|
| **微信服务号审核周期** | P01是核心基础设施，审核延迟将阻塞推送功能 | 尽早提交服务号申请（开发前2周），开发阶段使用测试号 |
| **微信认证接口变更** | C01/D01依赖微信OAuth接口稳定性 | 封装适配层，预留切换其他认证方式的接口 |
| **匹配算法冷启动** | 关键词匹配在初期岗位数量少时效果不佳 | 一期采用简单关键词匹配+人工推荐兜底，积累数据后二期引入智能推荐 |
| **应聘者信息补充流失** | C04要求补充4类信息可能导致转化漏斗损耗 | 分步引导+进度条+跳过选项，监控每一步流失率并优化 |
| **留言对话活跃度** | 双向沟通功能上线后可能使用率低 | 预设快捷回复模板，推送"新消息"提醒，降低沟通门槛 |

## 九、MVP成功度量指标

| 指标 | 目标值 | 度量方式 |
|------|--------|---------|
| **注册转化率** | 访问->注册 >= 40% | 服务号关注数 / 注册完成数 |
| **岗位发布率** | 招聘者注册->发布岗位 >= 60% | 注册招聘者中完成至少1条岗位发布的比例 |
| **关键词订阅率** | 应聘者注册->设置订阅 >= 50% | 注册应聘者中设置至少1个关键词的比例 |
| **推送打开率** | 推送->查看 >= 30% | 模板消息点击率 |
| **信息补充完成率** | 查看概要->补充信息看完整 >= 50% | C04分步表单完成率 |
| **对话发起率** | 查看完整信息->发起对话 >= 20% | 查看职位详情后发起留言的比例 |
| **周活跃留存** | 次周留存 >= 25% | 次周有登录/操作行为的用户比例 |

## 十、二期功能展望

以下功能在一期验证后根据数据反馈决定是否纳入二期：

| 功能 | 优先级预期 | 前提条件 |
|------|:---:|------|
| 费用管理（在线支付） | 高 | 验证付费意愿后 |
| 会员管理体系 | 高 | 用户规模达到5000+ |
| 智能推荐（替代纯关键词匹配） | 高 | 积累足够的岗位和简历数据 |
| 标签库 + JD模板库 | 中 | 岗位类型丰富后 |
| 数据统计分析（高级版） | 中 | 数据量支撑分析价值 |
| 转发推荐（深度裂变） | 中 | 验证自然增长效果后 |
| 视频面试 / AI简历解析 | 低 | 技术和资金充裕后 |

> **报告结论**：一期聚焦12个Must Have功能，用4个Sprint（8周）完成"发布-订阅-推送-沟通"核心闭环。费用和会员管理一期不做，用运营手段兜底。核心风险点在于微信服务号审核周期和应聘者信息补充的转化流失，需提前应对。
