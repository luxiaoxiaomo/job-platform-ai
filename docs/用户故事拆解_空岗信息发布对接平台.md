## 1. 角色定义

| 角色 | 描述 | 核心目标 |
|------|------|----------|
| **招聘者** | 企业HR或招聘负责人，通过平台发布空岗信息并管理招聘流程 | 高效发布岗位、筛选候选人、完成招聘 |
| **应聘者** | 求职者，通过平台浏览岗位信息并与招聘方互动 | 发现合适岗位、展示自身能力、获得工作机会 |
| **平台管理员**（隐式） | 负责审核、风控和平台运营 | 确保信息真实合规、维护平台秩序 |
| **AI系统**（v2.0新增） | 平台AI能力层，提供OCR、NLP、推荐、对话等智能服务 | 提升用户体验、降低使用门槛、增强匹配效率 |

#### US-A01 AI OCR识别营业执照自动填充企业信息

| 属性 | 值 |
|------|-----|
| **角色** | 招聘者 |
| **需求** | 我希望上传营业执照后，AI自动识别并填充企业统一社会信用代码、法人、注册地址等信息 |
| **价值** | 以便大幅减少手动输入企业信息的工作量和出错率 |
| **优先级** | P1 |
| **Story Points** | 3 |
| **前置依赖** | US-1.3, US-A24 |

**验收标准（AC）：**

```gherkin
AC-A01.1 正常流程：上传清晰营业执照并自动填充
Given 招聘者处于企业认证页面
When 招聘者上传一张清晰的营业执照照片（JPG/PNG格式，5MB以内）
Then AI OCR服务在3秒内完成识别
And 自动提取并填充字段：统一社会信用代码、企业名称、法定代表人、注册资本、成立日期、注册地址、经营范围
And 提示"已自动识别营业执照信息，请核对确认"

AC-A01.2 正常流程：识别结果可编辑
Given AI OCR已填充企业信息
When 招聘者发现某字段识别有误
Then 可手动点击对应字段进行修改
And 修改后字段旁标注"已人工修改"

AC-A01.3 异常流程：图片模糊无法识别
Given 招聘者上传的营业执照图片模糊
When AI OCR识别置信度低于60%
Then 提示"图片不够清晰，部分信息无法准确识别"
And 仅填充高置信度字段，低置信度字段标黄提示"请手动核实"

AC-A01.4 降级方案：AI OCR服务不可用
Given OCR服务处于宕机或超时状态（>5秒无响应）
When 招聘者上传营业执照
Then 系统提示"智能识别服务暂时不可用，请手动填写企业信息"
And 直接跳转至手动填写表单模式
And 所有字段为空，不阻塞用户注册流程
```

#### US-A02 AI名片识别自动填充联系信息

| 属性 | 值 |
|------|-----|
| **角色** | 招聘者 |
| **需求** | 我希望上传个人名片后，AI自动识别并填充姓名、电话、邮箱、公司等信息 |
| **价值** | 以便快速完成联系信息填写，减少手动录入 |
| **优先级** | P1 |
| **Story Points** | 3 |
| **前置依赖** | US-1.5, US-A24 |

**验收标准（AC）：**

```gherkin
AC-A02.1 正常流程：上传名片并自动填充联系信息
Given 招聘者在联系信息填写页面点击"上传名片"
When 上传一张清晰的个人名片图片
Then AI OCR在3秒内完成识别
And 自动提取并填充：姓名、手机号、邮箱、公司名称、职位
And 提示"已自动识别名片信息，请核对确认"
And 每个识别字段旁展示置信度标识（绿色=高置信，黄色=需核实）

AC-A02.2 正常流程：识别结果与已填信息交叉校验
Given 招聘者已填写企业名称
When AI OCR识别名片中的公司名称与已填企业名称不一致
Then 提示"名片中公司名称与已填企业名称不一致，请确认"
And 提供"以名片为准"和"保留已填信息"选项

AC-A02.3 异常流程：名片格式非标准
Given 上传的名片为竖版或非标准排版
When AI OCR识别部分字段失败
Then 仅填充成功识别的字段
And 未识别字段保持为空并提示"部分信息未能识别，请手动补充"

AC-A02.4 降级方案：AI名片识别服务不可用
Given OCR服务不可用
When 招聘者上传名片
Then 系统提示"智能识别暂时不可用，名片已保存，请手动填写联系信息"
And 名片图片正常上传保存（供后续人工审核使用）
And 不阻塞联系信息提交流程
```

#### US-A03 AI智能检测重复/冲突企业信息并提示合并

| 属性 | 值 |
|------|-----|
| **角色** | 招聘者 |
| **需求** | 我希望在填写企业信息时，AI能智能检测是否存在重复或冲突的企业记录，并提示合并 |
| **价值** | 以便避免平台上出现重复企业账号，提升数据质量 |
| **优先级** | P1 |
| **Story Points** | 5 |
| **前置依赖** | US-1.3, US-A24 |

**验收标准（AC）：**

```gherkin
AC-A03.1 正常流程：AI多维度检测重复企业
Given 招聘者填写企业名称后点击"下一步"
When AI从名称相似度、统一社会信用代码、地址、法人等多维度检测
Then 若检测到高相似度企业记录，展示"疑似重复企业"列表
And 每条记录展示：企业名称、匹配维度、相似度百分比
And 提供"是同一企业-申请合并"和"不是同一企业-继续注册"选项

AC-A03.2 正常流程：AI智能合并建议
Given AI检测到重复企业
When 招聘者选择"是同一企业"
Then AI自动生成合并方案（哪些字段保留、哪些更新）
And 向原企业管理员发送合并申请
And 当前用户进入"待合并确认"状态

AC-A03.3 正常流程：AI冲突检测报告
Given AI检测到多个维度存在不一致（如名称相似但法人不同）
When 展示冲突详情
Then 以对比表格形式展示差异字段
And AI标注"建议人工核实"的风险等级

AC-A03.4 降级方案：AI检测服务不可用
Given AI重复检测服务不可用
When 招聘者填写企业信息
Then 系统回退到基础查重（精确名称匹配 + 信用代码匹配）
And 提示"智能检测暂时不可用，已使用基础查重"
And 不阻塞注册流程，后续由人工补充审核
```

#### US-A04 AI假冒企业信息初筛（多维度交叉验证）

| 属性 | 值 |
|------|-----|
| **角色** | 招聘者 |
| **需求** | 我希望平台在注册时AI自动进行企业真实性初筛，识别潜在假冒企业 |
| **价值** | 以便提升平台企业信息的可信度，保护求职者利益 |
| **优先级** | P1 |
| **Story Points** | 3 |
| **前置依赖** | US-1.3, US-A24 |

**验收标准（AC）：**

```gherkin
AC-A04.1 正常流程：AI多维度交叉验证
Given 招聘者提交企业信息
When AI执行多维度验证（企业名称+信用代码+法人+地址+行业匹配度）
Then 对每个维度给出验证结果和置信度
```

| **价值** | 以便确保AI功能的稳定性和可用性，避免因AI服务故障影响核心业务流程 |
| **优先级** | P0 |
| **Story Points** | 5 |

**验收标准（AC）：**

```gherkin
AC-A24.1 正常流程：AI模型服务网关
Given 平台各功能模块调用AI能力（OCR、LLM、推荐等）
When AI请求通过统一网关
Then 网关执行：
  - 请求路由（根据功能类型路由到对应AI服务）
  - 负载均衡（多个AI服务实例间分配请求）
  - 认证鉴权（校验调用方权限）
And 所有请求记录日志

AC-A24.2 正常流程：AI服务降级策略
Given 某AI服务（如LLM文本生成）连续3次请求失败或超时（>10秒）
When 网关检测到服务异常
Then 自动触发降级策略：
  - 将服务状态标记为"降级中"
  - 后续请求直接返回降级响应（由调用方处理）
  - 通知运维团队
And 每60秒探测一次服务恢复状态
And 恢复后自动切回正常模式

AC-A24.3 正常流程：AI服务限流
Given 平台设定AI服务调用限流规则
When 某用户或功能在短时间内请求量超过阈值
Then 超出部分请求被限流（返回"服务繁忙，请稍后重试"）
And 限流策略支持：
  - 用户级限流（每用户每分钟最多X次AI调用）
  - 功能级限流（JD代写每分钟最多Y次）
  - 全局限流（系统总AI调用不超过Z QPS）

AC-A24.4 正常流程：AI服务监控仪表盘
Given 平台运维人员需要监控AI服务状态
When 打开AI服务监控面板
Then 展示：
  - 各AI服务健康状态（正常/降级/故障）
  - 实时QPS、平均响应时间、错误率
  - 今日调用总量和费用估算
  - 降级事件时间线

AC-A24.5 降级方案：AI网关本身故障
Given AI服务网关出现故障
When 各功能模块调用AI服务
Then 所有AI功能进入全局降级模式
And 各功能模块按各自的降级方案运行（如AI-JD代写→模板模式）
And 核心业务流程（注册、发布、查看）不受影响
```
