## 三、数据库变更（Codex）

### 3.1 新增 7 张表

1. **`resume_structured_profiles`** - 结构化 JSON 源表
   - 存储解析结果 JSON + 置信度 + 状态

2. **`resume_basic_infos`** - 基础信息
   - 姓名/性别/年龄/学历/工作年限/城市/目标岗位

3. **`resume_educations`** - 教育经历
   - 学校/专业/学历/起止时间

4. **`resume_work_experiences`** - 工作经历
   - 公司/职位/起止时间/工作内容

5. **`resume_projects`** - 项目经历
   - 项目名/角色/起止时间/项目描述

6. **`resume_skills`** - 技能
   - 技能名/熟练度/分类

7. **`resume_certificates`** - 证书
   - 证书名/类型/获得时间

### 3.2 字段设计亮点

- ✅ **可追溯**：每张表都带 `seeker_id` + `upload_id` + `parse_run_id` + `structured_profile_id`
- ✅ **置信度**：每张表都有 `confidence_score` + `source`（rule/llm/manual）
- ✅ **无敏感字段**：不存身份证/婚育/户籍/民族/政治面貌
- ✅ **筛选索引**：核心字段（学历/工作年限/学校/公司/技能）加索引

## 四、后端 API（Codex）

### 4.1 P2 核心 API

```http
# 1. 查询结构化结果（用于确认页）
GET /api/v1/resumes/me/parse-runs/{parse_run_id}/structured
返回：{basic, educations, work_experiences, projects, skills, certificates}

# 2. 确认并投影到明细表
PUT /api/v1/resumes/me/structured/confirm
入参：{parse_run_id, confirmed_basic, confirmed_educations, ...}
动作：标记已确认 + 投影到 6 张明细表

# 3. 画像聚合查询（用于画像页）
GET /api/v1/resumes/me/profile-summary
返回：{resume, profile, basic_info, summaries, completeness, review}
```

### 4.2 数据投影逻辑

- **高置信度字段（≥0.85）**：自动投影到明细表
- **低置信度字段（<0.85）**：留在 JSON 中，等用户确认后再投影
- **确认后**：标记 `confirmed=true`，投影到明细表

## 七、完整数据链路

```
用户上传简历
    ↓
后端解析原文（docx/pdf → text）
    ↓
规则解析 → 生成 structured_profiles (JSON)
    ↓
高置信度字段 → 自动投影到明细表
    ↓
前端确认页展示 → 用户确认
    ↓
确认后 → 标记 confirmed + 投影剩余字段
    ↓
画像页聚合查询 → 展示完整简历画像
    ↓
投递页读取基础信息 → 显示在投递表单
```

## 八、P2 与 P1 的差异

| 维度 | P1 阶段 | P2 阶段 |
|------|---------|---------|
| **数据存储** | 只有 `parsed_snapshot` 文本快照 | 7 张结构化明细表 |
| **数据质量** | 无置信度、无追溯 | 每字段带置信度 + 可追溯到解析任务 |
| **确认流程** | 无确认页，直接回写 `seeker_profiles` | 有确认页，先确认再投影 |
| **画像页** | mock 雷达图 + mock 标签 | 真实数据：完整度/技能/教育/工作/项目/证书 |
| **投递页** | 读 `seeker_profiles`（不准） | 读 `resume_basic_infos`（精确） |
