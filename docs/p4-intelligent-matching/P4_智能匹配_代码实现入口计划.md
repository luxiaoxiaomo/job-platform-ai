### 2.2 BE-P4-02：strategy API、权限、审计

范围：实现 strategy list/create/detail/update/clone API，不接 runtime matching。

接口：

```text
GET    /api/v1/matches/intelligent/strategies
POST   /api/v1/matches/intelligent/strategies
GET    /api/v1/matches/intelligent/strategies/{strategy_id}
PATCH  /api/v1/matches/intelligent/strategies/{strategy_id}
POST   /api/v1/matches/intelligent/strategies/{strategy_id}/clone
```

权限：

- P0 只允许 `admin`。
- `seeker`、`recruiter` 全部返回 403。
- 后续 viewer/operator 角色不在第一批实现。

校验：

- `name` 必填且不可重复。
- `base_rule_config_id` 必须存在。
- `top_n` 范围 1 到 500。
- `min_similarity` 范围 0 到 1。
- `hybrid_weights` 合计必须等于 1.0，允许 0.001 浮点误差。
- `fallback_policy` 只接受 `rule_baseline`。
- `testing/active/archived` 不允许原地编辑，只能 clone 新 draft。

审计：

| 操作 | action | before_snapshot | after_snapshot |
| --- | --- | --- | --- |
| create | create_intelligent_strategy | null | normalized payload |
| update | update_intelligent_strategy | previous strategy | updated strategy |
| clone | clone_intelligent_strategy | source strategy | cloned draft |
| archive | archive_intelligent_strategy | previous strategy | archived strategy |

测试：

- admin 创建成功。
- seeker/recruiter 创建失败 403。
- 非法权重失败 400/422。
- 不存在 base rule 失败 404。
- testing 策略 PATCH 失败 409。
- clone 生成新的 draft。
- 操作审计写入。

回滚：

- 移除 router/service/repository 注册即可停止入口。
- 数据表保留不影响现有 P3 matching。

## 5. 运行时开关与降级策略

当前实现没有接入以下环境变量 feature flag：

```text
INTELLIGENT_MATCHING_ENABLED
INTELLIGENT_MATCHING_RUNTIME_ENABLED
INTELLIGENT_MATCHING_EVALUATION_ENABLED
```

当前代码以数据库中是否存在 `active` 智能策略作为运行时选择条件：

- 没有 `active` 策略时，继续使用规则 baseline。
- 存在 `active` 策略时，执行 `intelligent_hybrid_v1`。
- 本地 `local_profile_text` provider 可返回混合评分。
- provider 未配置或不可用时，返回规则 baseline 并记录 `vector_store_unavailable`。

生产化时仍建议增加显式 feature flag，但不能用 feature flag 替代策略发布、权限、审计和回滚治理。

其他降级原则：

- audit 写入失败时，不允许产生不可追溯的 intelligent result。
- evaluation 样本不足时，`decision_status` 为 `insufficient_sample`。
- demo/mock 样本主导时，`decision_status` 为 `demo_only`。
