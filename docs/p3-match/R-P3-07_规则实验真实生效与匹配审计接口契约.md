# R-P3-07 Rule Experiment Execution and Match Audit Contract

## Goal

R-P3-07 makes rule experiments affect real match calculations. Runtime matching now selects an effective rule by scope and template, applies AB traffic routing for running experiments, persists a match audit record, and exposes experiment effect metrics for admin review.

## Runtime Rule Selection

Endpoint:

`GET /api/v1/matches/jobs/{job_id}/me`

Selection order:

1. `scope = job_id:{job_id}`, `template_key = default`
2. `scope = global`, `template_key = default`
3. code default rule fallback

For each scope:

1. If a `running` experiment exists for the same `scope/template_key`, the request is routed to `control_config_id` or `treatment_config_id`.
2. Otherwise, the latest `active` rule config for the same `scope/template_key` is used.
3. Invalid persisted rule configs are skipped and fallback continues.

AB routing:

- `traffic_percent = 0`: always `control`
- `traffic_percent = 100`: always `treatment`
- `1..99`: stable hash of `experiment_id + seeker_id + job_id`

Response additions under `source`:

```json
{
  "rule_config_id": 12,
  "experiment_id": 3,
  "experiment_bucket": "treatment",
  "audit_id": 40,
  "scope": "global",
  "template_key": "default"
}
```

When no experiment is active, `experiment_id` and `experiment_bucket` are `null`, but `rule_config_id`, `audit_id`, `scope`, and `template_key` are still returned.

## Match Audit Query

Endpoint:

`GET /api/v1/matches/audits`

Auth:

- `admin`

Query parameters:

- `experiment_id?: int`
- `rule_config_id?: int`
- `job_id?: int`
- `skip?: int = 0`
- `limit?: int = 20`

## Frontend Acceptance

Admin route:

`/admin-ra/rule-experiments`

Required behavior:

- create a rule experiment entry from existing rule versions
- open one experiment's effect panel
- show control/treatment match counts, average score, and level distribution
- show recent audit rows for the selected experiment
